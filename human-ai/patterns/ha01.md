# HA01 — Retrieval exercise gives away its own answer

[Human + AI catalog]({{ '/human-ai/' | relative_url }}) · [Evaluation and limitations]({{ '/human-ai/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/human-ai.md)

Check whether the material visible during a recall exercise already supplies its target answer.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/human-ai/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Keeps a tutor from mistaking copying a displayed answer for an independent recall attempt.

This is a proposed benefit, not an observed human outcome. All fixtures on this page are synthetic. No study with people was conducted for this catalog, and the question must not be used to infer a person's traits, ability, diagnosis, or intent.

## Required named state

Supply the following named fields as the evidence packet:

- `task_prompt`
- `target_answer`
- `learner_visible_support`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. Preserve the exact source revision. Any remaining insufficiency or ambiguity follows the question's `unknown` criteria; a model label cannot establish missing facts.

## Complete synthetic example

This is fixture `HA01-4`, from the **challenge** split. Its author received the question contract without the original design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "task_prompt": "What change of state occurs when the water in a shallow dish disappears into the air? State the starting and ending states.",
  "target_answer": "Liquid water changes into water vapor, a gas.",
  "learner_visible_support": "Do not confuse this with condensation. In this example, the liquid becomes water vapor in the air; it does not become a solid."
}
```

Expected label: `disclosed`.

The support gives the liquid-to-vapor transition in meaning-equivalent words. Its warnings and negations do not remove that disclosure.

## Code-owned responsibilities

Keep answer keys outside learner-visible rendering. Code freezes the exact display snapshot and records whether support was actually shown; Jev cannot inspect a hidden UI.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One review of a revised visible prompt is allowed; a host tutor revises it and a person approves use.

## Verification recipe

Render the actual learner view, inspect every visible hint, and use a held-out human-labeled set including paraphrased leaks; measure recall separately.

This describes required verification work, not checks already performed. Separate agreement with synthetic expected labels from successful execution of the real workflow and from any measured benefit to a person.
