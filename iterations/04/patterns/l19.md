# L19: Classify answer work type before model routing

Pick a response workflow based on the requested work shape rather than treating all questions as free-form generation.

## State contract

Supply a compact named JSON object with these required fields:

- <code>user_request</code>
- <code>available_context</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>work_type</code>.

~~~json
{
  "work_type": {
"type": "choice",
"instructions": "What answer work type is requested by user_request given available_context? Classify the requested output shape, not its truth or safety. Do not invoke another model, produce the answer, or select an external tool.",
"criteria": {
  "extractive": "The request asks to locate, quote, select, or copy a bounded fact/span from supplied context.",
  "constrained_transformation": "The request asks to reformat, organize, normalize, or transform supplied material without adding substantive new claims.",
  "evidence_synthesis": "The request asks to combine or explain multiple supplied pieces of evidence while preserving uncertainty/provenance.",
  "open_generation_or_no_fit": "The request needs unconstrained creative/generative work, missing external research, or another capability outside a bounded System One decision."
}
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Use code to select a bounded extraction/transform/synthesis workflow or request missing context; never treat the label as an answer.

**Code and governance own:** Model routing, response generation, source retrieval, tool selection, permissions, and delivery.

**Simpler baseline:** Send every request directly to one general text-generation model.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L18's direct-versus-multistep System One depth classification and L04's handler selection, this routes answer construction by output work shape before any answer is made.

## Limits and source

A work-type label does not establish that context is sufficient or that a later answer is correct.
