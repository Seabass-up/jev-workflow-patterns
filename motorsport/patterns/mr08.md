# MR08 — Hypothesis states a measurable prediction

[Motorsport catalog]({{ '/motorsport/' | relative_url }}) · [Evaluation and limitations]({{ '/motorsport/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/motorsport.md)

Classify whether an engineering hypothesis predicts a measurable outcome, only a direction, or nothing.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/motorsport/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Improves the chance that a test run can confirm or refute what it was meant to test; whether the prediction came true is decided from logged data in code.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `hypothesis_statement`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

A statement that names a quantity that can be measured or logged and says how it is expected to change, or what value or range it is expected to reach, makes a measurable prediction. A statement that predicts an effect only in qualitative terms, such as better balance, more confidence, or improved feel, without naming a measurable quantity, gives a direction without a quantity. ## Policy recorded with its option count

Review when confidence is below 0.8. With 4 options, that floor is equivalent to a top probability of 0.85; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `MR08-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "hypothesis_statement": "If we raise the rear ride height by 2 mm and soften the rear bar one hole, the car will feel more planted through the fast T4-T5 sequence and the driver will have more confidence to commit on entry."
}
```

Expected label: `direction_without_quantity`.

The numbers in the statement describe the input adjustments, not the predicted outcome; the predicted effect ('more planted', 'more confidence') is qualitative and names no measurable quantity that could be logged to check it.

## Code-owned responsibilities

Code records the named quantity and expected change alongside the run plan, evaluates the prediction from logged data after the run, and returns direction_without_quantity statements to the engineer to name a quantity; the engineer decides what the outcome means.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One re-check after the engineer restates the hypothesis.

## Verification recipe

Compare labels with the test-plan reviewer's rating of a season of hypotheses; measure hypotheses the label called measurable that later could not be evaluated from the data.

This describes required verification work, not checks already performed.

## Source inspiration

- [Wikipedia: Telemetry (motor racing section)](https://en.wikipedia.org/wiki/Telemetry) (MR-S5). Describes race engineers interpreting data collected during a test or race to tune the car, including accelerations, temperatures, wheel speeds, and suspension displacement, and systems that compute an expected lap time the driver is measured against. Motivates MR05 and MR06 (a run is compared with a named reference from logged channels) and MR08 (a hypothesis should name a logged quantity). Motivation only, not evidence of Jev performance.
- [NIST: Measurement Uncertainty (Statistical Engineering Division topic page)](https://www.nist.gov/itl/sed/topic-areas/measurement-uncertainty) (MR-S2). States that a measurand has a numerical magnitude and a reference that gives that magnitude meaning, and that uncertainty characterises the dispersion of values attributable to it. Motivates MR01 (a reference must be stated), MR02 and MR04 (a value is not a result until compared in code), MR03 (the property must be identified before its limit is applied), and MR08 (a prediction needs a named quantity). Motivation only, not evidence of Jev performance.

These sources motivate the design problem and its boundaries. They do not demonstrate Jev performance on this question.
