# L18: Classify System One decision depth

Route tasks needing multistep reasoning or exact computation away from a narrow Jev-only judgment.

## State contract

Supply a compact named JSON object with these required fields:

- <code>task_description</code>
- <code>available_state</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>decision_depth</code>.

~~~json
{
  "decision_depth": {
    "type": "choice",
    "instructions": "Classify requested work shape, not whether the evidence suffices to answer it. First select insufficient if task_description is missing, empty, or too vague to identify the operation; or if available_state is missing/empty and the task alone does not establish the operation or comparison scope. Do not choose insufficient merely because values or source material needed for a clearly specified task are absent. Select multistep_or_indirect_derivation whenever the task requires chained steps, external retrieval, exact calculation, or a derived result, even if it also compares records or includes a direct judgment. Otherwise select single_bounded_comparison only for one comparison of two or more supplied records/candidates without a chain. Select direct_stated_judgment only for one focused semantic judgment about one supplied item, with no comparison or chain. If none clearly applies, select insufficient. Do not calculate, fill evidence gaps, or claim Jev suffices for consequential action.",
    "criteria": {
      "direct_stated_judgment": "One focused semantic judgment about one supplied item; no comparison across multiple records and no chained, retrieved, calculated, or derived result.",
      "single_bounded_comparison": "One explicit comparison of two or more supplied records or candidates; no chained, externally retrieved, calculated, or derived result.",
      "multistep_or_indirect_derivation": "The task requires chained reasoning, external retrieval, exact calculation, or any derived result; this takes precedence over comparison or direct judgment also present.",
      "insufficient": "The requested operation or comparison scope cannot be determined from task_description and available_state; missing answer values alone do not make a clear operation insufficient."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Route multistep_or_indirect_derivation to a reasoning/retrieval workflow or review, preserving the task and missing-evidence explanation.

**Code and governance own:** Task decomposition, calculations, retrieval, permissions, thresholds, and action selection.

**Simpler baseline:** Send every natural-language request to one model call.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L04, which picks an offered handler for a request, this categorizes the semantic depth and known limitations of a task before any handler choice.

## Limits, source, and shared skill

It is an advisory routing aid, not a benchmark or proof another model will solve the task. Missing calculation inputs do not turn a clearly requested calculation into an insufficient-depth label; the requested operation shape controls the route.

Version 2 gives explicit precedence to multistep work over comparisons and direct judgments, and limits insufficient to an unclear task shape. The original two fixtures remain unchanged; four development cases cover vague tasks, bounded comparison, missing calculation values, and comparison-plus-derivation.
