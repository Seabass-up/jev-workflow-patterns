# L13: Align a retrieved entity mention to a candidate entity

Keep candidate-entity alignment, field disagreement, and actual linking separate.

## State contract

Supply a compact named JSON object with these required fields:

- <code>source_mention</code>
- <code>candidate_entity</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>alignment</code>, <code>name_agreement</code>, <code>context_agreement</code>.

~~~json
{
  "alignment": {
    "type": "score",
    "instructions": "How does source_mention relate to candidate_entity? Use an ordered relationship: different, related but needs review, or same entity. Do not create a link, merge records, or assume a shared name is a unique identifier.",
    "criteria": [
      "Different entity: explicit identity, organization, location, or role evidence contradicts a match.",
      "Related but needs review: the pair has meaningful overlap but a material field is missing, conflicting, or insufficient for a safe link.",
      "Same entity: the supplied context consistently supports the same named entity."
    ]
  },
  "name_agreement": {
    "type": "noul",
    "instructions": "Do source_mention and candidate_entity explicitly agree on the relevant name or alias?",
    "criteria": {
      "true": "They explicitly identify the same name or stated alias.",
      "false": "They do not explicitly agree on it or the name is absent."
    }
  },
  "context_agreement": {
    "type": "noul",
    "instructions": "Do source_mention and candidate_entity explicitly agree on a non-name contextual field such as organization, location, or role?",
    "criteria": {
      "true": "At least one supplied non-name contextual field explicitly agrees.",
      "false": "No supplied non-name contextual field explicitly agrees or it conflicts."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Present related cases with field signals to a curator; require an independent deterministic identity check before linking.

**Code and governance own:** Candidate retrieval, entity IDs, exact normalization, merge/link operation, and provenance.

**Simpler baseline:** Link entities whenever text names look similar.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L03's field extraction, this uses an ordered relationship plus companion checks for one mention/candidate pair; unlike B15 it is an LLM retrieval/linking component rather than commercial remittance reconciliation.

## Limits, source, and shared skill

A high score or agreement signal is not proof of identity.
