# H24: Atomic score composition with veto policy

Keep semantic dimensions reusable while code decides which preferences may compensate and which failures must veto.

## State contract

Supply a compact named JSON object with these required fields:

- <code>candidate</code>
- <code>evaluation_rubric</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>fit</code>, <code>operational_burden</code>, <code>named_veto</code>.

~~~json
{
  "fit": {
    "type": "score",
    "instructions": "Rate how well candidate fits the stated desired outcome in evaluation_rubric. Judge only supplied semantic fit; do not decide the final policy outcome.",
    "criteria": [
      "No demonstrated fit.",
      "Limited fit with important unmet desired outcomes.",
      "Strong fit for the stated desired outcome."
    ]
  },
  "operational_burden": {
    "type": "score",
    "instructions": "Rate the operational burden explicitly stated for candidate under evaluation_rubric. Do not invent cost, timing, or resources.",
    "criteria": [
      "Low stated burden.",
      "Moderate stated burden.",
      "High stated burden."
    ]
  },
  "named_veto": {
    "type": "noul",
    "instructions": "Does candidate explicitly trigger a non-compensable veto condition named in evaluation_rubric?",
    "criteria": {
      "true": "A named veto condition is directly met by the supplied candidate.",
      "false": "No named veto condition is directly met by the supplied candidate."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Code stores raw dimensions, applies versioned weights only to compensable dimensions, and sends any high veto signal to review.

**Code and governance own:** Weights, thresholds, veto policy, numeric calculation, source identity, and all action decisions.

**Simpler baseline:** Ask one opaque question such as whether a candidate is good overall.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike H19's policy hazard/severity routing matrix, this generalizes code-owned weighted preference with an explicit non-compensable veto across independent score dimensions.

## Limits, source, and shared skill

Weights and thresholds require domain calibration; scores never authorize action.
