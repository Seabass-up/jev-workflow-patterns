# LR07 — Sequence constraint stated in a multi-stop request

[Logistics routing catalog]({{ '/logistics-routing/' | relative_url }}) · [Evaluation and limitations]({{ '/logistics-routing/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/logistics-routing.md)

Classify whether a multi-stop request constrains the order or grouping of its stops, so code can encode the rule for the routing solver.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/logistics-routing/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Keeps customer-stated precedence from being lost when stops are entered, while the solver, not the model, computes the sequence.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `multi_stop_request`
- `stop_list`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 4 options, that floor is equivalent to a top probability of 0.85; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `LR07-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "multi_stop_request": "Four drops on the same run please. Any order you like for the three shops, but the Hollins Yard warehouse has to be the first drop, before anything else comes off the truck.",
  "stop_list": [
    "Hollins Yard warehouse, 2 Tannery Reach",
    "Pennywort Bakery, 3 Tallow Lane",
    "Fernbright Florist, 19 Tallow Lane",
    "Marlow Street Newsagent, 7 Marlow Street"
  ]
}
```

Expected label: `ordering_constraint`.

Saying the warehouse must be the first drop is an ordering constraint, and the allowance of any order among the other three stops does not remove it. The request also states a grouping constraint (same run), and the contract selects ordering_constraint when both are present.

## Code-owned responsibilities

Code extracts which stops the constraint names, encodes it as a precedence or same-route rule for the routing solver, and computes the sequence; the model never chooses a route.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One re-check after the planner adds a stop the label could not match.

## Verification recipe

Compare labels with the constraints planners entered for the same requests; review any request whose routed sequence the customer later disputed.

This describes required verification work, not checks already performed.
