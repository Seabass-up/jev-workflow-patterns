# H36: Ingress/egress message-risk ledger

Keep independently screened input and output risks separate so code can apply phase-specific policy.

## State contract

Supply a compact named JSON object with these required fields:

- <code>message_phase</code>
- <code>message</code>
- <code>risk_policy</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>risk_posture</code>.

~~~json
{
  "risk_posture": {
"type": "choice",
"instructions": "What risk posture is explicitly indicated by message under risk_policy for message_phase? Classify the supplied text only. Do not block a user, call a model/tool, reveal policy details, or certify safety.",
"criteria": {
  "no_named_hazard": "The message does not clearly exhibit a named hazard under the supplied policy excerpt.",
  "named_hazard": "The message clearly exhibits at least one named hazard under the supplied policy excerpt.",
  "ambiguous_hazard": "The message is plausibly within a named hazard but the supplied policy/text leaves material ambiguity.",
  "policy_not_applicable": "The supplied policy excerpt does not cover this phase/message type."
}
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Code records phase and policy revision, aggregates separate signals, applies phase-specific thresholds, and preserves review/block decisions for authorized policy handlers.

**Code and governance own:** Security controls, policy decisions, blocking, tool access, user messaging, logging, and incident response.

**Simpler baseline:** Rely solely on a primary LLM's system prompt for both input and output policy handling.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike H19's hazard/severity routing matrix, this is an ingress/egress evidence ledger that keeps phase, message revision, and independently applied policy signals separate; unlike L14 it is not a RAG evidence lane.

## Limits and source

It is not a complete guardrail, safety proof, or authority to impose a policy outcome.
