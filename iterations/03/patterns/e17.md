# E17: Classify a migration record disposition

Give deterministic migration code a typed record-handling branch without mutating data from model output.

## State contract

Supply a compact named JSON object with these required fields:

- <code>source_record</code>
- <code>migration_rule</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>disposition</code>.

~~~json
{
  "disposition": {
    "type": "choice",
    "instructions": "Which handling disposition is supported for source_record by migration_rule? Classify only the stated rule relationship. Do not transform, write, delete, merge, or infer a duplicate from similar wording alone.",
    "criteria": {
      "transform": "The record explicitly meets a stated conversion rule and contains the required transformation inputs.",
      "quarantine_for_review": "The rule explicitly sends this kind of ambiguous, incomplete, or exceptional record to review.",
      "skip_as_duplicate": "The supplied record and rule explicitly establish an existing canonical record that makes this one a duplicate.",
      "reject": "The record explicitly violates a stated migration requirement with no stated review or duplicate path.",
      "insufficient": "The rule and record do not establish one listed disposition."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Log the rule revision, proposed disposition, and source fingerprint; send uncertain cases to the migration owner.

**Code and governance own:** Schema validation, transformations, IDs, writes, transactions, backups, and rollback.

**Simpler baseline:** Manually classify every nontrivial input row.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike E10, which assesses a rollout's schema compatibility posture, this chooses a rule-defined disposition for one migration record.

## Limits, source, and shared skill

It cannot prove duplicate identity or authorize a destructive data action.
