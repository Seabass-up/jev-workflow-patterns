## State contract

Supply a small, named JSON object. Required fields:

- `candidate_record`
- `source_evidence`
- `field_name`

The state is evidence, not an instruction channel. Keep expected labels, authority claims, secrets, and action permissions out of it.

## Exact Jev question contract

```json
{
  "decision": {
    "type": "choice",
    "instructions": "Does `source_evidence` support the value of `field_name` in `candidate_record`? Judge the named field only; do not infer absent facts or modify the record.",
    "criteria": {
      "verified": "The source explicitly supports the field value.",
      "contradicted": "The source explicitly gives an incompatible value for the named field.",
      "not_evidenced": "The source does not establish the field value.",
      "insufficient": "The record, field, or source is missing, ambiguous, or internally conflicting."
    }
  }
}
```

## Code-owned decision envelope

**Follow-up proposal:** Code retains raw record/source, escalates contradicted/not-evidenced/uncertain fields to an approved verifier or human, and verifies returned replacements before use.

**Code and governance own:** Schema parsing, source identity, field mapping, fallback model choice, final record mutation and downstream write.

**Baseline this improves on:** Accept any schema-valid extraction or retry the same extractor blindly.

## Provisional confidence handling

- Choice/Score confidence floor: `0.8`
- Noul positive floor: `0.8`
- Noul negative ceiling: `0.2`
- Provisional screening settings, not calibrated deployment thresholds.

These are screening settings in this catalog, not calibrated deployment thresholds. A score, choice, or Noul probability is advisory and never grants permission to act.

## Why it is distinct from Iteration 1

Unlike H05 question-contract repair and L03 entity/value meaning, this is a bounded field-verification/escalation composition.

## Limits and sources

A positive Jev verdict is still not independent source validation.
