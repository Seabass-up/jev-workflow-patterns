# H25: Two-pass character-preserving structure recovery

Recover document structure without having a generative model rewrite the source.

## State contract

Supply a compact named JSON object with these required fields:

- <code>lines</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>pass_order</code>.

~~~json
{
  "pass_order": {
    "type": "choice",
    "instructions": "What processing order is appropriate for the described lines when their structure may be lost? Classify whether code must first establish adjacent continuations before asking block-level structure questions. Do not rewrite the text.",
    "criteria": {
      "stitch_then_classify": "Adjacent-line continuity must be resolved before meaningful block classification can occur.",
      "classify_directly": "The supplied lines are already explicitly separated into structurally meaningful blocks.",
      "insufficient": "The supplied line state does not establish a safe processing order."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Batch independent adjacency questions, construct blocks in code, then batch independent block classifications; retain line IDs throughout.

**Code and governance own:** Line normalization, blank gaps, explicit markers, joins, block construction, rendering, and provenance.

**Simpler baseline:** Ask an LLM to rewrite the entire unstructured document as Markdown.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L15's one adjacency question, this is the two-request, code-sequenced preservation controller that consumes many such questions.

## Limits, source, and shared skill

It does not preserve rich formatting absent from the source or validate a rendered document's meaning.
