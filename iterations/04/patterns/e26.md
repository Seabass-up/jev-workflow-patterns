# E26: Classify semantic lint enforcement tier

Choose a safe enforcement shape for a rule instead of pretending every guideline is deterministically lintable.

**Contract version 2:** An unclear decision/evidence request is underspecified; intelligible but broad consequence judgments stay with people; semantic advice never directly fails CI. The current cases cover all answer labels; see the evaluation record for synthetic results. This is not production qualification.

## State contract

Supply a compact named JSON object with these required fields:

- <code>engineering_rule</code>
- <code>candidate_check</code>
- <code>enforcement_context</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>enforcement_tier</code>.

~~~json
{
  "enforcement_tier": {
    "type": "choice",
    "instructions": "Choose the narrowest justified enforcement tier. First choose underspecified if the intended decision or necessary evidence is unclear. Choose human_review_only when the requested decision is intelligible but its outcome depends on broad design intent, unshown context, or consequence judgment that cannot be bounded to a reviewable semantic rubric. Choose deterministic_check when a stated predicate is exactly evaluable in ordinary code. Choose jev_advisory_plus_code_gate only when semantic criteria, supplied evidence scope, and a code-owned gate or review route are explicitly bounded. Code owns exact gates; Jev remains advisory and never directly makes CI pass/fail. Do not modify code or claim universal validity.",
    "criteria": {
      "deterministic_check": "A clear stated predicate can be evaluated from explicit syntax, types, or fixed data with ordinary code alone.",
      "jev_advisory_plus_code_gate": "The intended decision is bounded by stated semantic criteria and evidence scope, and the supplied context defines a deterministic code-owned gate or review route. Jev output is advisory and is not itself the gate.",
      "human_review_only": "The requested decision is understandable, but judging it requires broad design intent, unshown context, or consequence judgment that cannot be bounded to a reliable semantic rubric.",
      "underspecified": "The supplied rule/check context does not make clear what decision is requested or what evidence/condition would answer it; classify this before selecting an enforcement mechanism."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Draft deterministic checks where possible; retain Jev outputs as advisory evidence and ask a rule owner to define underspecified rules.

**Code and governance own:** CI configuration, pass/fail policy, code modifications, permissions, and release decisions.

**Simpler baseline:** Treat every engineering guideline as human review regardless of its formalizability.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike E05's change-type classification and H05's repair of a demonstrated question defect, this decides the appropriate enforcement architecture for a proposed semantic lint.

## Limits and source

A tier recommendation is not an authorization to fail builds or a proof that a rule is correct.
