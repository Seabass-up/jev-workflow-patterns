# E25: Classify trace-event relationship type

Separate causality evidence from same-request and merely temporal log correlation.

## State contract

Supply a compact named JSON object with these required fields:

- <code>event_a</code>
- <code>event_b</code>
- <code>trace_context</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>relationship</code>.

~~~json
{
  "relationship": {
"type": "choice",
"instructions": "What relationship is explicitly evidenced between event_a and event_b by trace_context? Do not infer causation from time alone, calculate timestamps, or declare an incident root cause.",
"criteria": {
  "direct_causal_link": "The trace explicitly records one event as causing, triggering, or directly producing the other through a named operation/result link.",
  "shared_request_correlation": "The events share a request/trace context but the supplied evidence does not establish that one caused the other.",
  "temporal_proximity_only": "The events are only close in time or order without a shown common request or causal link.",
  "insufficient": "The supplied records cannot establish one listed relationship."
}
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Route direct-link candidates to source tracing and other states to correlation review; retain event IDs and trace revisions.

**Code and governance own:** Trace ID validation, timestamp ordering, causal graph construction, incident diagnosis, and remediation.

**Simpler baseline:** Manually reconstruct every trace relationship before triage.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike E14's incident-document causal assertion and E15's failure-origin indication, this classifies the relationship of two bounded trace events while explicitly preserving noncausal correlation.

## Limits and source

Logs can be incomplete or misleading; a direct-link label is not independent root-cause proof.
