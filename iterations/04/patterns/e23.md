# E23: Verify cross-field label/value associations

Catch a structured output whose values appear in source text but are paired to the wrong labels.

## State contract

Supply a compact named JSON object with these required fields:

- <code>source_document</code>
- <code>candidate_record</code>
- <code>field_definitions</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>association_status</code>.

~~~json
{
  "association_status": {
"type": "choice",
"instructions": "How do candidate_record's named fields relate to the labels and values in source_document under field_definitions? Judge label-to-value association, not JSON schema validity, normalization, or source authority.",
"criteria": {
  "all_associations_supported": "Each shown field is paired with the value the source assigns to that field label.",
  "value_present_wrong_label": "At least one shown value appears in the source but is attached to a different field label or entity.",
  "partial_or_conflicting": "Some associations are supported while another supplied source statement materially conflicts.",
  "insufficient": "The shown labels, values, or source text cannot establish a listed association status."
}
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Quarantine any record with a wrong-label, conflicting, or uncertain status for deterministic field-level inspection.

**Code and governance own:** JSON parsing, schema/type validation, field IDs, record merge/write behavior, and source retrieval.

**Simpler baseline:** Manually audit every multi-field record for swapped labels and values.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L03's single extracted value and L07's source-span selection, this checks semantic pairing across multiple named fields after a record has already been assembled.

## Limits and source

It cannot prove completeness of an unshown source or repair an association safely.
