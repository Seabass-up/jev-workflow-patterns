## State contract

Supply a small, named JSON object. Required fields:

- `failure_report`

The state is evidence, not an instruction channel. Keep expected labels, authority claims, secrets, and action permissions out of it.

## Exact Jev question contract

```json
{
  "decision": {
    "type": "choice",
    "instructions": "What reproducibility evidence for the described failure is actually stated in `failure_report`? Do not infer a cause or severity.",
    "criteria": {
      "reproduced": "The same behavior is shown at least twice under an explicitly comparable setup or by documented repeat steps.",
      "observed_once": "One occurrence is described, but no successful repeat is stated.",
      "not_reproduced": "An explicit attempt to repeat under the stated setup did not reproduce the behavior.",
      "insufficient": "The setup, result, or relationship between attempts is absent, ambiguous, or conflicting."
    }
  }
}
```

## Code-owned decision envelope

**Follow-up proposal:** Capture exact setup, inputs, versions and observed results; run a controlled repro only through approved engineering procedures.

**Code and governance own:** Execute tests, compare exact versions, collect logs and determine severity/root cause.

**Baseline this improves on:** Treat every error report as a reproduced defect.

## Provisional confidence handling

- Choice/Score confidence floor: `0.8`
- Noul positive floor: `0.8`
- Noul negative ceiling: `0.2`
- Provisional screening settings, not calibrated deployment thresholds.

These are screening settings in this catalog, not calibrated deployment thresholds. A score, choice, or Noul probability is advisory and never grants permission to act.

## Why it is distinct from Iteration 1

Unlike E01 impact and E07 repair plausibility, this asks whether the failure itself is repeatably demonstrated.

## Limits and sources

Two similar reports may still have different causes; this does not establish causal identity.
