# RE03 — Severity an inspection-report item states as written

[Real estate catalog]({{ '/real-estate/' | relative_url }}) · [Evaluation and limitations]({{ '/real-estate/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/real-estate.md)

Classify the severity that an inspector's own wording assigns to one item in a property inspection report.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/real-estate/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Turns a long report into a sortable list for the agent and the parties without changing the inspector's words or grading the property.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `report_item`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 5 options, that floor is equivalent to a top probability of 0.84; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `RE03-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "report_item": "Main electrical panel: two neutral conductors share a single terminal (double-tapped) at three locations. All circuits were functional at the time of inspection and the condition does not present an immediate hazard, but correction requires a licensed electrician."
}
```

Expected label: `major_defect`.

The inspector expressly negates a hazard, so safety_concern is not stated as written even though the item is electrical. The wording fits minor_defect (functions but needs repair) and major_defect (repair requires a licensed contractor), and the contract's precedence selects major_defect first.

## Code-owned responsibilities

Code keeps the inspector's wording unchanged, records the report identifier and item number, and leaves any repair request, price negotiation, or decision to proceed to the parties and their licensed advisers. The label never grades the property or decides a safety question.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

None; items whose wording gives no severity go to the agent to ask the inspector.

## Verification recipe

Compare labels with the severity the inspection firm's own summary assigned to each item; measure items the label placed below the inspector's stated severity first.

This describes required verification work, not checks already performed.
