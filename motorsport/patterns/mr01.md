# MR01 — Measurement report states a complete procedure

[Motorsport catalog]({{ '/motorsport/' | relative_url }}) · [Evaluation and limitations]({{ '/motorsport/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/motorsport.md)

Classify whether a metrology write-up states the instrument used, the reference it measured from, and the conditions of measurement, or which of these it leaves out.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/motorsport/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Catches reports that cannot be reproduced or audited before their value enters the setup or conformance record; the value itself is never judged by the model.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `measured_quantity`
- `measurement_report`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 5 options, that floor is equivalent to a top probability of 0.84; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `MR01-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "measured_quantity": "Front wing left flap angle",
  "measurement_report": "Front wing left flap angle recorded at 14.2 degrees. Measured against the car's reference plane with the car on the setup pads at race ride height, fuel at 30 kg, tyres at working pressure, ambient 21 C. Ride height had been set beforehand using the Halvorsen HS-3 digital height stick zeroed on the pad plate. Value logged to setup sheet run 7."
}
```

Expected label: `instrument_not_stated`.

The only instrument named (the height stick) was used to set ride height, not to obtain the flap angle, so the procedure for the named quantity lacks its instrument even though the reference plane and conditions are stated; instrument_not_stated is also first in the contract's priority order.

## Code-owned responsibilities

Code stores the reported value and unit exactly as written, compares it with the tolerance record in code, requires a complete_procedure label or a reviewer sign-off before the value enters the conformance record, and never treats a complete procedure as a correct value.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One re-check after the technician adds the missing element; no further calls.

## Verification recipe

Compare labels with the quality lead's review of a season of metrology reports; measure reports accepted as complete that the lead sent back first.

This describes required verification work, not checks already performed.

## Source inspiration

- [Wikipedia: Metrology](https://en.wikipedia.org/wiki/Metrology) (MR-S1). Describes metrology as defining units, realising them in practice, and tracing practical measurements to reference standards, with calibration and harmonised test procedures and report formats giving confidence in results. Motivates MR01 as a check that a report states its instrument, reference, and conditions, and MR02 as a reading of whether a note blames the instrument. Motivation only, not evidence of Jev performance.
- [NIST: Measurement Uncertainty (Statistical Engineering Division topic page)](https://www.nist.gov/itl/sed/topic-areas/measurement-uncertainty) (MR-S2). States that a measurand has a numerical magnitude and a reference that gives that magnitude meaning, and that uncertainty characterises the dispersion of values attributable to it. Motivates MR01 (a reference must be stated), MR02 and MR04 (a value is not a result until compared in code), MR03 (the property must be identified before its limit is applied), and MR08 (a prediction needs a named quantity). Motivation only, not evidence of Jev performance.

These sources motivate the design problem and its boundaries. They do not demonstrate Jev performance on this question.
