# EL06 — What the permitting office is asking for

[Electrical catalog]({{ '/electrical/' | relative_url }}) · [Evaluation and limitations]({{ '/electrical/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/electrical.md)

Classify what a message from a permitting office asks the contractor to do.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/electrical/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Lets the office answer the right request quickly instead of reading every jurisdiction message from scratch.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `office_message`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 5 options, that floor is equivalent to a top probability of 0.84; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `EL06-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "office_message": "Subject: Revisions required for standby generator permit, City of Example Building Division. Before the reviewer can accept corrected plans, please upload the manufacturer's installation instructions for the transfer equipment to the permit portal. After those are received, revise sheet E-2 to show the transfer switch location and the feeder routing and resubmit the plan set. The resubmittal fee must be paid at that time before review resumes."
}
```

Expected label: `submit_document`.

The subject line frames the message as a resubmittal, but the body asks first for the manufacturer's instructions to be uploaded, with the plan revision and the fee following; the contract selects the request the message asks for first.

## Code-owned responsibilities

Code tracks deadlines, uploads documents, and records payments; the label only routes the message.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

None; unknown messages go to the office manager.

## Verification recipe

Compare labels with how the office actually handled a quarter of jurisdiction messages.

This describes required verification work, not checks already performed.
