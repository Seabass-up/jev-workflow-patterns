# CT09 — What a message asks the recipient to do with a credential

[Call controls catalog]({{ '/controls/' | relative_url }}) · [Evaluation and limitations]({{ '/controls/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/controls.md)

Classify whether a message asks the recipient to disclose a credential, to reset one through their own channel, or neither.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/controls/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Supplies the one phishing signal that should veto delivery rather than average into a spam score, while leaving legitimate reset instructions alone.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `message_text`
- `credential_terms`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 4 options, that floor is equivalent to a top probability of 0.85; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `CT09-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "message_text": "Reminder from Larkspur IT: your network password expires in 3 days. To avoid lockout, open the link below, sign in with your current password, and pick a new one when prompted. New passwords must be at least 14 characters.",
  "credential_terms": [
    "password",
    "one-time passcode",
    "security question answers"
  ]
}
```

Expected label: `disclose_credential`.

The message presents itself as a routine reset, but it instructs the recipient to enter the current password at a linked destination, which the contract defines as disclosure. Because the message both directs a reset and asks for the current credential, the contract's tie rule selects disclose_credential.

## Code-owned responsibilities

Code supplies the credential list from policy, parses links and senders, applies disclose_credential as a non-compensable veto, and owns quarantine, warnings, and review. No label proves a message is safe.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

None; a veto goes to quarantine and review, not to another model call.

## Verification recipe

Run a labelled phishing and legitimate-notification corpus; measure veto recall on credential-harvesting messages and false vetoes on genuine reset notices.

This describes required verification work, not checks already performed.
