# H23: Broad-index then detailed-shortlist recheck controller

Use broad cheap screening without treating the first winner as a final selection.

## State contract

Supply a compact named JSON object with these required fields:

- <code>request_summary</code>
- <code>broad_index</code>
- <code>detailed_shortlist</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>recheck_outcome</code>.

~~~json
{
  "recheck_outcome": {
    "type": "choice",
    "instructions": "Given request_summary and detailed_shortlist, what detailed recheck outcome is supported? Select only the offered top candidate, a different offered candidate, or none. The broad_index is context for why candidates were inspected, not proof that its first item must win.",
    "criteria": {
      "top_candidate_still_fits": "The first shortlisted candidate's detailed description directly fits the request.",
      "different_shortlisted_candidate_fits": "A different offered shortlisted candidate directly fits better than the first.",
      "none_fit_after_detail": "No offered detailed description materially fits the request.",
      "insufficient": "The request or detailed descriptions cannot establish an outcome."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Keep broad rank, cutoff, detailed inputs, and rejected candidates; only a code-defined accepted outcome becomes a nonbinding suggestion.

**Code and governance own:** Broad index generation, top-k threshold, full-text fetch, selection record, loading, and execution.

**Simpler baseline:** Select the first short-description match and never re-read it.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L17's question contract for a specific agent-skill shortlist, this is a reusable two-stage controller for any bounded candidate catalog.

## Limits, source, and shared skill

A weak broad index can omit the right candidate; the controller records that limitation rather than masking it.
