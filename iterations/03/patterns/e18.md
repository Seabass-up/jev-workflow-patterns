# E18: Classify replay and idempotence evidence

Distinguish observed replay outcomes from retry permission.

## State contract

Supply a compact named JSON object with these required fields:

- <code>operation_description</code>
- <code>replay_trace</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>replay_evidence</code>.

~~~json
{
  "replay_evidence": {
    "type": "choice",
    "instructions": "What replay or idempotence evidence is explicitly shown by operation_description and replay_trace? Classify the observed or stated effect only. Do not authorize another replay, assume an idempotency key works, or infer side effects absent from the trace.",
    "criteria": {
      "single_effect_demonstrated": "The trace explicitly shows repeated invocation resolving to one intended persistent effect under the stated conditions.",
      "duplicate_effect_risk": "The trace or operation description explicitly shows multiple effects, an absent idempotency boundary, or a stated duplicate-effect risk.",
      "no_effect_before_side_effect": "The trace explicitly shows failure or cancellation before the stated persistent effect occurs.",
      "insufficient": "The supplied description and trace do not establish one listed evidence state."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Reproduce with a controlled test and inspect the real idempotency boundary before any retry policy change.

**Code and governance own:** Replay execution, keys, transaction semantics, retries, and side-effect reconciliation.

**Simpler baseline:** Treat every failure as safely retryable or forbid all retries.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike E09's semantic retry posture, this classifies evidence from an operation and replay trace about observed effect multiplicity.

## Limits, source, and shared skill

A synthetic or partial trace cannot prove production idempotence.
