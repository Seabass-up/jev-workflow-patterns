# HA17 — Preserve the work the person wants to do

[Human + AI catalog]({{ '/human-ai/' | relative_url }}) · [Evaluation and limitations]({{ '/human-ai/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/human-ai.md)

Check whether a proposed helper response takes over a part of the task the user explicitly reserved for themselves.

**Provisional:** the initial synthetic screen includes an unresolved label mismatch for this pattern. Consult the [evaluation record]({{ '/human-ai/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Support creative ownership and participation instead of equating help with maximum automation.

This is a proposed benefit, not an observed human outcome. All fixtures on this page are synthetic. No study with people was conducted for this catalog, and the question must not be used to infer a person's traits, ability, diagnosis, or intent.

## Required named state

Supply the following named fields as the evidence packet:

- `user_task_brief`
- `proposed_help`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. Preserve the exact source revision. Any remaining insufficiency or ambiguity follows the question's `unknown` criteria; a model label cannot establish missing facts.

## Complete synthetic example

This is fixture `HA17-4`, from the **challenge** split. Its author received the question contract without the original design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "user_task_brief": "I want to invent the slogan myself. Please organize my notes into customer needs, but do not write sample slogans or a final slogan.",
  "proposed_help": "I grouped your notes into three customer needs. I also wrote three optional sample slogans; you can ignore them and invent your own."
}
```

Expected label: `takes_over`.

Calling the samples optional does not undo performing the explicitly retained slogan-writing work; the user specifically excluded samples.

## Code-owned responsibilities

Keep the exact current request, selected artifact, scope and edit permissions. This label never grants permission to rewrite or publish. Make suggestions reversible.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

At most one clarification about the reserved part if unclear; otherwise adjust the proposed help without asking the user to restate the entire goal.

## Verification recipe

Review a blinded set of briefs and proposed help with users; measure unwanted task takeover separately from output quality. Verify the delivered artifact did not perform the reserved work.

This describes required verification work, not checks already performed. Separate agreement with synthetic expected labels from successful execution of the real workflow and from any measured benefit to a person.

## Source inspiration

- [Guidelines for Human-AI Interaction (Amershi et al., CHI 2019)](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/) (HD-S1). Original research presents 18 interaction guidelines, evaluated with 49 design practitioners and 20 AI-infused products. Guidance motivates correction, user control, and scoped help; it does not evaluate Jev.
- [Google PAIR: User Needs + Defining Success](https://pair.withgoogle.com/chapter/user-needs/) (HD-S2). Official design guidance distinguishes augmentation from replacing work people want to do, and warns that narrow reward functions can miss broader outcomes. These are design principles, not empirical Jev performance claims.

These sources motivate the design problem and its boundaries. They do not demonstrate Jev performance on this question. Source summaries and recorded provenance are available in [sources JSON]({{ '/human-ai/sources.json' | relative_url }}); supplemental accessibility guidance is not a full conformance assessment.
