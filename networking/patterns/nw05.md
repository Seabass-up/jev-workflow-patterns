# NW05 — Advisory product family appears in the inventory description

[Networking catalog]({{ '/networking/' | relative_url }}) · [Evaluation and limitations]({{ '/networking/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/networking.md)

Check whether a product family a vendor advisory names is one the team's inventory description also names.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/networking/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Sorts incoming advisories by whether a named family is deployed before a person reads each one; version and serial comparisons stay in code.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `advisory_product_text`
- `inventory_text`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 4 options, that floor is equivalent to a top probability of 0.85; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `NW05-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "advisory_product_text": "Affected products: Corvid 9000 series switches running CorvidOS releases 4.2 through 4.8. Not affected: Corvid 3000 series access switches, and any Corvid 9000 unit running CorvidOS 5.0 or later.",
  "inventory_text": "Deployed: Corvid 9000 series core switches at both data centers, all on CorvidOS 5.1; Ridgeline 7000 series routers at the internet edge; Ridgeline access points across all offices."
}
```

Expected label: `family_matches`.

The advisory names the Corvid 9000 series and the inventory names that same family as deployed, which is all the contract asks. Whether the deployed 5.1 release falls inside or outside the affected 4.2 to 4.8 range is a version comparison the contract reserves for code and excludes from this judgment, so the advisory's own not-affected clause does not turn the label into family_differs.

## Code-owned responsibilities

Code compares version numbers, release trains, serial and part numbers, and the inventory system of record exactly, and schedules any remediation; the label only says whether a named family appears in the inventory description.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One re-check after code supplies a fuller inventory description when the label is unknown.

## Verification recipe

Compare labels with the platform team's affected or not-affected determinations for a year of advisories; review every family_differs that the team later marked affected.

This describes required verification work, not checks already performed.
