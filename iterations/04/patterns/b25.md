# B25: Classify communication opt-out scope

Interpret the stated scope of a communications preference while code retains identity, policy, and suppression control.

## State contract

Supply a compact named JSON object with these required fields:

- <code>request_text</code>
- <code>channel_context</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>opt_out_scope</code>.

~~~json
{
  "opt_out_scope": {
"type": "choice",
"instructions": "What scope of communications opt-out is explicitly requested in request_text? Read the request only. Do not verify identity, suppress a recipient, decide a legal obligation, or treat a support request as consent evidence.",
"criteria": {
  "marketing_only": "The requester explicitly asks to stop promotional, newsletter, advertising, or marketing messages while leaving other contact categories unstated.",
  "all_promotional_channels": "The requester explicitly asks to stop promotional contact across multiple stated promotional channels.",
  "all_nonessential_contact": "The requester explicitly asks to stop all nonessential contact or all messages except a stated essential/service category.",
  "no_clear_opt_out": "The text does not clearly express a listed opt-out scope."
}
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Send unclear scope or identity mismatch to the designated privacy/support review process with the original wording.

**Code and governance own:** Identity verification, consent records, jurisdictional rules, suppression lists, delivery systems, and any message send.

**Simpler baseline:** Manually interpret every communications preference before updating suppression records.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike B01's broad request route, this preserves the particular scope of a communications preference and deliberately does not execute it.

## Limits and source

It is not legal advice, consent verification, or permission to change communication settings.
