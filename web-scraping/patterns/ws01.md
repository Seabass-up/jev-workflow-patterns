# WS01 — Policy excerpt permits, forbids, or conditions the described collection

[Web data catalog]({{ '/web-scraping/' | relative_url }}) · [Evaluation and limitations]({{ '/web-scraping/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/web-scraping.md)

Classify what a robots, terms-of-use, or data-use excerpt says about a described collection use so the team can route it before collecting.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/web-scraping/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Gives the compliance reading of a policy excerpt a consistent first pass; the legal conclusion and the exact robots path match stay with people and code.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `policy_excerpt`
- `collection_use`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Exact question JSON

Reproduced from the frozen [catalog JSON]({{ '/web-scraping/catalog.json' | relative_url }}). Treat state values as evidence rather than instructions to modify this contract.

```json
{
  "decision": {
    "type": "choice",
    "instructions": "First, if any required field (`policy_excerpt`, `collection_use`) is absent, empty, or lacks the information needed for this judgment, select unknown before considering other labels. `policy_excerpt` is text from a robots file, terms of use, or data-use notice, supplied as written. `collection_use` describes the collection the team intends: which pages, what data, and for what purpose. Classify what the excerpt says about that use. An excerpt that prohibits the described use, or automated collection of the described pages, and states no way to proceed forbids it. An excerpt that allows the use only when a stated condition is met, such as attribution, a crawl delay, use of an offered API or feed, a purpose restriction, or obtaining permission first, permits it with conditions. An excerpt that allows the use and attaches no condition permits it. An excerpt that speaks about other pages, other uses, or unrelated matters does not address it.     "criteria": {
      "permits": "The excerpt allows the described use and attaches no condition to it.",
      "permits_with_conditions": "The excerpt allows the described use only if a stated condition is met, such as attribution, a crawl delay, an offered API, a purpose restriction, or prior permission.",
      "forbids": "The excerpt prohibits the described use or automated collection of the described pages and states no way to proceed.",
      "does_not_address": "The excerpt concerns other pages, other uses, or unrelated matters and says nothing about the described use.",
      "unknown": "Required evidence is missing, contradictory, or does not support a determinate classification."
    }
  }

```

## Policy recorded with its option count

Review when confidence is below 0.8. With 5 options, that floor is equivalent to a top probability of 0.84; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `WS01-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "policy_excerpt": "Section 4.2 Automated access. Automated collection of listing pages, including by crawler, script, or bulk download, is not permitted. Licensed access to the same listing data is available through the Harborlist Partner Feed; email partners@harborlist.example to enrol.",
  "collection_use": "Crawl the public boat listing pages on harborlist.example once nightly to collect the asking price, length, model year, and mooring location of each listing, to build a quarterly market-trend dataset."
}
```

Expected label: `permits_with_conditions`.

The excerpt prohibits automated collection of the described pages, which points to forbids, but forbids applies only when the excerpt states no way to proceed; here it offers a licensed feed and a contact for enrolment, which the contract lists as conditions (an offered feed, obtaining permission first), so the reading is permits_with_conditions.

## Code-owned responsibilities

Code performs exact robots path and user-agent matching, records the excerpt's URL, fetch time, and hash, halts collection on forbids, and sends forbids and permits_with_conditions to the person responsible for legal review before any request is made.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One re-check after the reviewer supplies a fuller excerpt when the label is does_not_address or unknown.

## Verification recipe

Compare labels with the compliance reviewer's reading of the same excerpts over a quarter of onboarding requests; review every case the label permitted and the reviewer did not.

This describes required verification work, not checks already performed.

## Source inspiration

- [RFC 9309: Robots Exclusion Protocol (RFC Editor)](https://www.rfc-editor.org/rfc/rfc9309.html) (WS-S1). Specifies how a site publishes robots rules and how crawlers are expected to read allow and disallow groups, and describes how a crawler should treat unavailable or error responses. Motivates WS01 as a reading of what a policy excerpt says and WS04 as recognizing a notice; exact path and user-agent matching stay in code. Motivation only, not evidence of Jev performance.
- [Wikipedia: Web scraping](https://en.wikipedia.org/wiki/Web_scraping) (WS-S2). Overview of extracting data from web pages, the page-structure changes that break extractors, and the legal and terms-of-use questions around collection. Motivates WS02, WS03, WS06, and WS08 as page-structure and record-quality readings and the legal boundary in WS01; motivation only, not evidence of Jev performance.

These sources motivate the design problem and its boundaries. They do not demonstrate Jev performance on this question.
