# SA07 — CRM note records an agreed next step

[Sales catalog]({{ '/sales/' | relative_url }}) · [Evaluation and limitations]({{ '/sales/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/sales.md)

Classify whether a pipeline note records a next step the prospect agreed to, a seller-only task, a closed outcome, or nothing.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/sales/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Finds opportunities with no agreed next step from the notes themselves, without moving a stage or judging the rep.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `crm_note`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

A next action that the note says the prospect agreed to, or that has a part the prospect will do, is a mutual next step. ## Policy recorded with its option count

Review when confidence is below 0.8. With 5 options, that floor is equivalent to a top probability of 0.84; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `SA07-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "crm_note": "Call with Dana today. Confirmed they signed with Brightline last week, so this one is lost on price. Set myself a reminder to check back in about nine months when their Brightline term comes up for renewal."
}
```

Expected label: `seller_side_next_step_only`.

The note states a closed outcome (lost) but also a next action for the seller only (a reminder to check back), with nothing the prospect agreed to; the contract's order puts seller_side_next_step_only before opportunity_closed_stated, and the closed criterion requires that no next action be stated.

## Code-owned responsibilities

Code owns the pipeline stage, the close date, and any task created from the note; a label never changes a stage or marks an opportunity closed.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

When the label is mutual_next_step_stated or seller_side_next_step_only, code passes the next-step sentence to SA05 for how its time is named; no other follow-up call.

## Verification recipe

Compare labels with a sales manager's review of a week of pipeline notes; review every no_next_step_stated on an opportunity the manager considered active.

This describes required verification work, not checks already performed.
