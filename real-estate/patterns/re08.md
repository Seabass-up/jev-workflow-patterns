# RE08 — Maintenance request describes an emergency sign

[Real estate catalog]({{ '/real-estate/' | relative_url }}) · [Evaluation and limitations]({{ '/real-estate/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/real-estate.md)

Classify whether a tenant's maintenance request describes an emergency sign, a loss of service without one, or a routine item.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/real-estate/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Puts the first triage of after-hours and high-volume requests on a consistent footing, while the response-time policy and the technician on site keep the decision.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `maintenance_request`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

Review when confidence is below 0.8. With 4 options, that floor is equivalent to a top probability of 0.85; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `RE08-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "maintenance_request": "Unit 3B. The furnace has not come on since last night; the thermostat is set to 68 and the display is lit, but no air is moving and the unit is sitting around 62 degrees. The weather has been mild all week, so we are managing fine with sweaters, but please send someone when you can. Also, the bathroom exhaust fan rattles."
}
```

Expected label: `loss_of_service`.

No heat is an emergency sign only while the request describes freezing or very cold weather, and this request describes mild weather, so the furnace outage is a utility that has stopped working with no emergency sign present. Loss_of_service precedes routine, which covers the rattling fan.

## Code-owned responsibilities

Code applies the property's response-time policy to each label, dispatches the on-call vendor for emergency_sign regardless of the hour, records the unit and request identifiers, and keeps the technician's own determination on site as authoritative. Utility shutoffs and safety procedures never depend on the label, and routing does not vary by anything about the sender.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

None; an emergency_sign label triggers the standing response, not another question.

## Verification recipe

Compare labels with the priority the maintenance coordinator assigned to a quarter of requests and with the technician's finding after the visit; measure missed emergency signs first.

This describes required verification work, not checks already performed.

Motivation for the design, not evidence of Jev performance.
- [HUD: Housing Discrimination Under the Fair Housing Act](https://www.hud.gov/helping-americans/fair-housing-act-overview) (RE-S1). HUD's overview states that housing discrimination is illegal in nearly all housing, that the Fair Housing Act protects people from discrimination when renting or buying a home, getting a mortgage, seeking housing assistance, or engaging in other housing-related activities, and lists the protected classes: race, color, national origin, religion, sex, familial status, and disability. Motivates the boundary applied across RE01, RE02, RE05, and RE08: every label reads text about a property, a document, or a request and never judges or infers anything about a person. This is motivation for the design, not legal advice.

These sources motivate the design problem and its boundaries. They do not demonstrate Jev performance on this question.
