# H40: Semantic-feature drift and retraining hold

Stop a semantic-feature pipeline from silently reusing an old evaluation after question, population, or held-out behavior changes.

## State contract

Supply a compact named JSON object with these required fields:

- <code>feature_pipeline_state</code>
- <code>change_evidence</code>
- <code>evaluation_receipt</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>drift_status</code>.

~~~json
{
  "drift_status": {
"type": "choice",
"instructions": "What drift/re-evaluation status is explicitly established by feature_pipeline_state, change_evidence, and evaluation_receipt? Do not calculate distribution metrics, retrain, deploy, or decide a business outcome.",
"criteria": {
  "stable_under_bound_receipt": "The shown question/data/policy revisions match the bound evaluation receipt and no material change evidence is supplied.",
  "question_or_policy_changed": "The supplied evidence shows a semantic question, criteria, model, or policy revision differing from the bound evaluation.",
  "population_or_source_changed": "The supplied evidence shows a material source population, collection, or input-distribution change after the bound evaluation.",
  "heldout_regressed_or_missing": "The receipt is missing, explicitly shows held-out regression, or cannot bind the current pipeline state."
}
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Code computes drift/metrics, fingerprints revisions, freezes deployment, schedules authorized retraining, and verifies any new evaluation receipt.

**Code and governance own:** Data monitoring, drift calculation, training, retraining, deployment, version control, and business decisions.

**Simpler baseline:** Reuse the last feature-model result whenever a textual input pipeline changes.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike H16's invalidation of one pending action after material state change and H20's human-adjudication confidence ledger, this is a feature-pipeline hold that binds question/data/policy revisions to held-out evidence.

## Limits and source

A stable receipt does not prove no real-world drift, and a hold does not identify the cause or corrective action.
