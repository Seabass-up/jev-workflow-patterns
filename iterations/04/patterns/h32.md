# H32: Choice plurality, agreement, and abstention audit

Expose the operational tradeoff between repeat agreement and confidence-based abstention for a Choice workflow.

## State contract

Supply a compact named JSON object with these required fields:

- <code>decision_name</code>
- <code>repeat_observations</code>
- <code>abstention_policy</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>agreement_status</code>.

~~~json
{
  "agreement_status": {
"type": "choice",
"instructions": "Given code-produced repeat_observations for one frozen Choice contract and abstention_policy, what agreement/abstention status is stated? Do not count labels, change the policy, auto-route an item, or hide abstentions.",
"criteria": {
  "high_agreement_auto_eligible": "The supplied summary says repeats agree and the selected-label probabilities meet the stated auto-action policy.",
  "agreement_but_abstain": "The supplied summary says a plurality/consensus exists but the stated confidence policy requires abstention or review.",
  "label_disagreement": "The supplied summary says repeats select materially different labels.",
  "insufficient": "The supplied observations/policy cannot establish one listed status."
}
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Code computes plurality/agreement and coverage, retains all samples, and applies an explicitly versioned abstention policy.

**Code and governance own:** Counting, thresholding, policy versioning, queue routing, human review, and all action execution.

**Simpler baseline:** Use one highest-probability Choice response with no agreement or abstention record.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike H12's general stability gate, this is Choice-specific: it keeps selected labels, agreement, confidence, and abstentions as separate code-owned measures.

## Limits and source

Agreement is not accuracy; repeated synthetic samples do not qualify a production routing policy.
