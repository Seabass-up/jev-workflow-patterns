# H22: Candidate-universe coverage gate

Keep a Choice winner from becoming a real-world selection unless the candidate universe is declared adequate.

## State contract

Supply a compact named JSON object with these required fields:

- <code>selection_request</code>
- <code>candidate_manifest</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>coverage</code>.

~~~json
{
  "coverage": {
    "type": "choice",
    "instructions": "What coverage status is explicitly described by candidate_manifest for selection_request? Classify the candidate-set declaration, not which candidate should win. Do not infer missing candidates or select a value.",
    "criteria": {
      "exhaustive_with_provenance": "The manifest explicitly says the applicable candidate universe is complete and gives each candidate a source identity.",
      "bounded_but_expandable": "The manifest explicitly says it is a known shortlist that may omit relevant candidates.",
      "ambiguous_or_duplicate_candidates": "The manifest explicitly contains unresolved duplicate identities or ambiguous candidate meanings.",
      "unverifiable": "The supplied manifest does not establish a reliable coverage status."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Code requires an exhaustive manifest or an explicit no-match branch before it treats a selected candidate as a real-world value.

**Code and governance own:** Candidate retrieval, uniqueness, source IDs, membership, expansion, and actual selection.

**Simpler baseline:** Use the highest-probability Choice label from any shortlist.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike H14, which verifies provenance after choosing one supplied span, this gates whether the upstream candidate universe is safe enough to treat any Choice winner as complete.

## Limits, source, and shared skill

A declaration of completeness still needs code/source validation.
