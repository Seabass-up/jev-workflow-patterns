# L19: Classify answer work type before model routing

Pick a response workflow based on the requested work shape rather than treating all questions as free-form generation.

**Contract version 2:** Compound requests use an explicit priority: missing external facts/original content, then evidence synthesis, then constrained transformation, then as-is extraction. The current cases cover all answer labels; see the evaluation record for synthetic results. This is not production qualification.

## State contract

Supply a compact named JSON object with these required fields:

- <code>user_request</code>
- <code>available_context</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>work_type</code>.

~~~json
{
  "work_type": {
    "type": "choice",
    "instructions": "Classify the primary answer work requested by user_request given available_context. Apply this precedence for compound requests: open_generation_or_no_fit when substantive new creative content or missing external facts are needed; evidence_synthesis when multiple supplied evidence items must be combined or explained; constrained_transformation when supplied material is reorganized/normalized without combining substantive claims; extractive only when a bounded fact/span is located or copied as-is. Do not invoke another model, produce the answer, or select an external tool.",
    "criteria": {
      "extractive": "The primary request only locates, quotes, selects, or copies a bounded fact/span from supplied context as-is; it does not require higher-priority synthesis, transformation, or open generation.",
      "constrained_transformation": "The primary request only reformats, organizes, or normalizes supplied material without adding claims or combining evidence into a new explanation; it does not meet the higher-priority synthesis or open-generation criteria.",
      "evidence_synthesis": "The primary request combines, compares, or explains multiple supplied evidence items while preserving uncertainty/provenance, even if the output is also formatted; choose open_generation_or_no_fit instead if material external facts or original creative content are required.",
      "open_generation_or_no_fit": "The request needs substantive original content or facts from external research not present in available_context; this takes precedence over work that can also be done with supplied material."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Use code to select a bounded extraction/transform/synthesis workflow or request missing context; never treat the label as an answer.

**Code and governance own:** Model routing, response generation, source retrieval, tool selection, permissions, and delivery.

**Simpler baseline:** Send every request directly to one general text-generation model.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L18's direct-versus-multistep System One depth classification and L04's handler selection, this routes answer construction by output work shape before any answer is made.

## Limits and source

A work-type label does not establish that context is sufficient or that a later answer is correct.
