# H21: Pin a decision response to the source snapshot

Reject a semantically plausible typed result when code cannot bind it to the current source snapshot.

## State contract

Supply a compact named JSON object with these required fields:

- <code>request_snapshot</code>
- <code>response_snapshot</code>
- <code>current_snapshot</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>snapshot_relation</code>.

~~~json
{
  "snapshot_relation": {
    "type": "choice",
    "instructions": "How do request_snapshot and response_snapshot relate to current_snapshot for the named decision? Classify the stated snapshot relation only. Do not validate a hash, reuse an answer, or claim a source is current.",
    "criteria": {
      "current_match": "The state explicitly states the response was produced from the same named snapshot now current for the decision.",
      "stale_after_change": "The state explicitly states a relevant source change occurred after the request or response snapshot.",
      "mismatched_snapshot": "The state explicitly states the response is tied to a different snapshot or target than the current decision.",
      "unverifiable": "The supplied snapshot statements do not establish one listed relation."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Code compares actual immutable revision fingerprints; anything but a verified current match is discarded or rerun against a fresh snapshot.

**Code and governance own:** Snapshot serialization, digests, revision lookups, cache keys, reruns, and result consumption.

**Simpler baseline:** Reuse any recent answer about the same topic.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike H16's semantic invalidation of a pending action, this binds an already-produced decision response to an exact source/request snapshot before it can be consumed.

## Limits, source, and shared skill

Jev cannot validate opaque fingerprints; code must make the final equality check.
