# EL08 — Photo description covers the requested evidence

[Electrical catalog]({{ '/electrical/' | relative_url }}) · [Evaluation and limitations]({{ '/electrical/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/electrical.md)

Check whether a technician's description of a photo shows the element an inspector or office asked to see.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/electrical/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Reduces rejected virtual-inspection submissions when the described photo does not show the requested item.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `requested_evidence`
- `photo_description`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 3 options, that floor is equivalent to a top probability of 0.8667; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `EL08-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "requested_evidence": "Photo of the bonding clamp on the metal water service pipe where it enters the building, showing the clamp, the pipe, and the bonding conductor attached to it.",
  "photo_description": "Close-up inside the main panel of the green bonding conductor landed on the ground bar, with the lug tightened and the conductor tagged 'water pipe bond'; the tag is legible and the conductor can be seen leaving the panel toward the utility room."
}
```

Expected label: `does_not_cover`.

The request names the clamp at the water pipe entry, and the described photo shows the other end of the same conductor at the panel ground bar, which is a different element; the contract says a photo of a different element does not cover the request.

## Code-owned responsibilities

Code attaches the actual photo, records the request identifier and revision, and leaves acceptance to the inspector. A description is not the photo.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One re-check after the technician submits another description.

## Verification recipe

Compare labels with inspector acceptance of virtual-inspection photos; review rejections the label accepted.

This describes required verification work, not checks already performed.
