# H35: Semantic lint canary and human-disagreement controller

Admit a semantic lint change only after a fixed labeled canary exposes new disagreements for review.

## State contract

Supply a compact named JSON object with these required fields:

- <code>lint_rule</code>
- <code>canary_case</code>
- <code>human_label</code>
- <code>candidate_finding</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>canary_relation</code>.

~~~json
{
  "canary_relation": {
"type": "choice",
"instructions": "For this one fixed canary_case, how does candidate_finding relate to human_label under lint_rule? Judge the shown semantic rule application only. Do not compute aggregate metrics, change the lint, fail CI, or declare the human label universally correct.",
"criteria": {
  "agrees_with_label": "The candidate finding and the human label express the same rule outcome for the shown case.",
  "new_disagreement": "The candidate finding materially differs from the human label for the shown rule/case.",
  "label_not_applicable": "The supplied label explicitly says the rule does not apply to this case.",
  "insufficient": "The rule, case, label, or finding is too incomplete to compare."
}
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Code freezes case IDs/labels, computes aggregate deltas, retains disagreements, and enforces a human-owned admission policy.

**Code and governance own:** Canary selection, metric calculation, CI gating, rule changes, label governance, and release decisions.

**Simpler baseline:** Ship semantic lint wording changes without a fixed, inspectable disagreement set.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike H05's targeted repair of a demonstrated question defect and H20's general confidence ledger, this is a version-admission controller that compares a semantic lint to fixed human canaries and queues new disagreements.

## Limits and source

Human labels can be incomplete or inconsistent; a canary is not complete production qualification.
