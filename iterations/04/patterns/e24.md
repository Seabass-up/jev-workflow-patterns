# E24: Classify test-double behavioral fidelity gap

Surface whether a mock removes a behavior material to the test's claimed conclusion.

**Contract version 2:** A behavior is missing only when the supplied contract and test claim establish what behavior must be preserved; unclear behavior is insufficient evidence. The current cases cover all answer labels; see the evaluation record for synthetic results. This is not production qualification.

## State contract

Supply a compact named JSON object with these required fields:

- <code>dependency_contract</code>
- <code>test_double</code>
- <code>test_claim</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>fidelity</code>.

~~~json
{
  "fidelity": {
    "type": "choice",
    "instructions": "Compare test_double with the contract behavior relevant to test_claim. Apply this order: insufficient if the supplied contract/claim do not identify the behavior or failure semantics needed for comparison; missing_relevant_failure_or_side_effect only when the contract and claim identify a material behavior that the double explicitly omits or changes; safely_simplified if at least one contract behavior is omitted but the descriptions establish that every omission is irrelevant to this claim; otherwise behaviorally_equivalent when all relevant contract behavior is retained. Do not infer a missing behavior merely from an incomplete description. Do not execute tests, infer unshown callers, or declare production behavior.",
    "criteria": {
      "behaviorally_equivalent": "The double retains every dependency-contract behavior relevant to the stated test claim; no contract behavior is omitted.",
      "safely_simplified": "The double omits at least one contract detail, and the supplied claim/contract establish that every omitted detail is irrelevant to the claim while all relevant behavior is retained.",
      "missing_relevant_failure_or_side_effect": "The double omits or changes a failure path, ordering rule, state effect, or side effect that the supplied contract makes material to the claim.",
      "insufficient": "The contract or claim does not identify the concrete behavior/failure semantics needed to decide whether the double omits a material behavior; do not presume an omission from missing detail alone."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Inspect the named double and contract path; add a deterministic integration or contract test where needed.

**Code and governance own:** Test execution, contract interpretation, mock implementation, coverage measurement, and release decisions.

**Simpler baseline:** Review every test double manually against its real dependency contract.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike E02's requirement-coverage check and E08's reproducibility evidence, this compares a substitute dependency behavior to the contract a test relies on.

## Limits and source

It cannot prove the real dependency works or that all unshown callers behave compatibly.
