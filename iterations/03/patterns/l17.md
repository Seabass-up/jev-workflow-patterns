# L17: Re-check a shortlisted agent skill choice

Give a code-chosen shortlist a detailed choose-or-none re-check before an agent loads a skill.

## State contract

Supply a compact named JSON object with these required fields:

- <code>user_task</code>
- <code>skill_shortlist</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>skill</code>.

~~~json
{
  "skill": {
    "type": "choice",
    "instructions": "Which offered entry in skill_shortlist best fits user_task after reading its detailed description, or choose no_skill? Select only an offered skill. A suggestion does not load it, override user instructions, or authorize an external action.",
    "criteria": {
      "document_editor": "The task explicitly needs the offered document editing capability.",
      "data_analysis": "The task explicitly needs the offered structured-data analysis capability.",
      "browser_test": "The task explicitly needs the offered browser testing capability.",
      "no_skill": "None of the offered detailed descriptions materially fits the task."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** The agent may inspect the suggested skill first but retains ordinary applicability judgment; no_skill keeps the roster unloaded.

**Code and governance own:** Initial broad roster ranking, candidate inclusion, skill loading, permissions, and task execution.

**Simpler baseline:** Load every superficially matching skill into the prompt.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L04's one-pass available handler selection, this is the second, detailed choose-or-none stage after code has formed a broad roster shortlist.

## Limits, source, and shared skill

It assumes the shortlist was adequate and cannot make an unloaded skill fit.
