# L20: Classify output fidelity contract

Make the caller's required faithfulness mode explicit before it asks a model to produce JSON or text.

**Contract version 2:** Two distinct fidelity modes select mixed_output_obligations first, including when they apply to the same output component; preserve and validate each obligation separately. The current cases cover all answer labels; see the evaluation record for synthetic results. This is not production qualification.

## State contract

Supply a compact named JSON object with these required fields:

- <code>request</code>
- <code>downstream_consumer</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>fidelity_contract</code>.

~~~json
{
  "fidelity_contract": {
    "type": "choice",
    "instructions": "Identify every distinct fidelity mode required anywhere in the requested output, including requirements applied to the same field. If two or more modes are required, choose mixed_output_obligations first; this label takes precedence over every single-mode label. Otherwise choose the one required mode: verbatim_source for literal source fidelity; typed_value for one bounded value normalized under a schema; cited_synthesis for an evidence-grounded explanation; creative_or_no_source when original composition is allowed or no source obligation is supplied. Do not generate output, validate a schema, or infer an unsupplied source.",
    "criteria": {
      "verbatim_source": "The only required fidelity mode is exact quotation, literal copied spans, or other byte/character-faithful source content; no separate normalization, typed-value, or synthesis mode is required.",
      "typed_value": "The only required fidelity mode is a normalized or typed value derived from a bounded source value under a stated schema/format; literal character matching is not separately required.",
      "cited_synthesis": "The only required fidelity mode is an evidence-grounded explanation with source attribution; no separate literal-copy or machine-typed field is required.",
      "creative_or_no_source": "Original composition is permitted and no distinct source-fidelity, citation, or typed-output mode is required.",
      "mixed_output_obligations": "Two or more distinct modes among verbatim source, typed value, cited synthesis, or creative/no-source are required anywhere in the requested output, including within one field; choose this before any single-mode label."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** For `mixed_output_obligations`, split the request into field/component-level contracts and validate each mode in code; request clarification if those obligations cannot be preserved together.

**Code and governance own:** Schema validation, exact copying, normalization, citations, generation, and delivery.

**Simpler baseline:** Use one generic free-text output path for every request.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L03's meaning/entity validation of one extracted value and L10's assertion-provenance label, this determines the output's required fidelity mode before a result is constructed.

## Limits and source

It cannot verify that a later output obeys the contract or that a cited source is authoritative.
