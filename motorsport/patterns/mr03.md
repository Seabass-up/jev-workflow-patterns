# MR03 — Which property a tolerance specification constrains

[Motorsport catalog]({{ '/motorsport/' | relative_url }}) · [Evaluation and limitations]({{ '/motorsport/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/motorsport.md)

Classify which physical property a specification text places a limit on, so code can match the text to the right measurement record.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/motorsport/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Lets a regulation extract or drawing note be filed against the right property without the model reading any number or computing any limit.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `specification_text`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 6 options, that floor is equivalent to a top probability of 0.8333; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `MR03-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "specification_text": "With each tyre stabilised at the series reference temperature of 90 C and checked with the official bleed gauge, the starting pressure of every front tyre shall not be below the published compound minimum, and each rear tyre shall not be below its own published minimum."
}
```

Expected label: `pressure`.

The temperature figure is a measurement condition, not a limit placed on the tyre, so the first-limit rule does not reach it; the only constraint the text imposes is on tyre pressure.

## Code-owned responsibilities

Code parses the numeric limit and unit, converts units, links the specification to the measurement record for that property, and performs every comparison; the label only selects which property record the text belongs to.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

None; other_property and unknown texts are filed by a person.

## Verification recipe

Run a season's regulation extracts and drawing notes through the check and compare labels with the property each was filed under by the quality team.

This describes required verification work, not checks already performed.

## Source inspiration

- [Wikipedia: Engineering tolerance](https://en.wikipedia.org/wiki/Engineering_tolerance) (MR-S3). Defines a tolerance as the permissible limit of variation, notes that tolerances can be applied to any dimension or physical property, and that a part outside tolerance is unusable by design intent while a stated tolerance does not by itself imply compliance. Motivates MR03 (which property is constrained), MR04 (a conformance claim is distinct from an observation), and MR07 (dimensional and mass notes). Motivation only, not evidence of Jev performance.
- [NIST: Measurement Uncertainty (Statistical Engineering Division topic page)](https://www.nist.gov/itl/sed/topic-areas/measurement-uncertainty) (MR-S2). States that a measurand has a numerical magnitude and a reference that gives that magnitude meaning, and that uncertainty characterises the dispersion of values attributable to it. Motivates MR01 (a reference must be stated), MR02 and MR04 (a value is not a result until compared in code), MR03 (the property must be identified before its limit is applied), and MR08 (a prediction needs a named quantity). Motivation only, not evidence of Jev performance.

These sources motivate the design problem and its boundaries. They do not demonstrate Jev performance on this question.
