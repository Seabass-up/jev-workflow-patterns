# LG07 — Supplier message announces a backorder, a substitution, or a cancellation

[Logistics catalog]({{ '/logistics/' | relative_url }}) · [Evaluation and limitations]({{ '/logistics/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/logistics.md)

Classify what a supplier's message announces about an open purchase order: a delayed shipment, a proposed replacement item, a cancellation, or another update.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/logistics/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Routes supplier messages to replanning, buyer approval, or reordering without a buyer triaging each one; dates, quantities, and prices are compared in code.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `supplier_message`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Complete synthetic example

This is fixture `LG07-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "supplier_message": "Re PO-EX-4410, line 2 (VX-200 controller, qty 40): we have closed this line on our side because the VX-200 has been discontinued by the manufacturer and will not be supplied. The successor model VX-210 is in stock at the same unit price and we would be glad to ship it right away; please raise a new PO for it if that suits. Lines 1 and 3 are unaffected and ship Thursday as confirmed."
}
```

Expected label: `cancellation`.

The message states that a line is closed and will not be fulfilled, and the contract selects cancellation even when the supplier suggests reordering something else. The successor-model offer therefore does not make it a substitution_proposal, and the shipment confirmation for other lines does not make it other_update.

## Code-owned responsibilities

Code compares the new date with the need-by date, checks a proposed item against the approved specification, updates the purchase order only after a buyer accepts a substitution, and records the supplier's message verbatim.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One clarification request to the supplier when the label is unknown.

## Verification recipe

Compare labels with how buyers actioned a month of supplier messages; review messages that mix unavailability with an offered alternative.

This describes required verification work, not checks already performed.

## Source inspiration

- [Wikipedia: Stockout (backorder)](https://en.wikipedia.org/wiki/Backorder) (LGS-5). Defines a backorder as an order placed for an out-of-stock item that is awaiting fulfillment, and discusses shoppers substituting another item when the ordered one is unavailable. Motivates LG07's distinction between a delayed shipment, a proposed substitute, and a cancellation. Motivation only, not evidence of Jev performance.
