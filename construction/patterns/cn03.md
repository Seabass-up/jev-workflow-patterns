# CN03 — Reviewer's action on a submittal

[Construction catalog]({{ '/construction/' | relative_url }}) · [Evaluation and limitations]({{ '/construction/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/construction.md)

Classify which review action a design reviewer's response to a submittal states, including whether resubmission is required.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/construction/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Lets the submittal log carry a consistent status from free-text review comments so ordering and fabrication wait for the right condition, while the project engineer confirms every release.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `reviewer_response`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

A response that marks corrections but states that resubmission is not required is approved as noted. A response that requires corrections and a new submission before the work proceeds is revise and resubmit. ## Policy recorded with its option count

Review when confidence is below 0.8. With 6 options, that floor is equivalent to a top probability of 0.8333; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `CN03-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "reviewer_response": "Storefront and entrance system submittal, returned by Marrow & Tice Architects (marrowtice.example). The framing depth shown is less than the specified depth and the glazing scheduled is not the specified low-iron product, so as presented the package does not conform. Because the package also omits the required structural calculations and the engineer's stamp, this office has not performed a review of its content and is returning it unreviewed. Furnish a complete package addressing the above for review."
}
```

Expected label: `returned_without_review`.

The response states the submittal was not reviewed and is being returned unreviewed, and the contract selects returned_without_review regardless of other remarks, so the non-conformance language (rejected) and the request for a new package (revise_and_resubmit) do not change the label.

## Code-owned responsibilities

Code owns the submittal number and revision, ball-in-court, the review log, and the rule that ordering or fabrication waits until the label is approved or approved_as_noted and the project engineer confirms; the label never releases material.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

None; an unknown label goes to the project engineer, who asks the reviewer.

## Verification recipe

Compare labels with the stamp codes recorded in a completed project's submittal log; review every mismatch where the label would have released material earlier than the log did.

This describes required verification work, not checks already performed.

## Source inspiration

- [Wikipedia: Submittals (construction)](https://en.wikipedia.org/wiki/Submittals_(construction)) (CN-S2). Describes the submittal process in which the contractor sends shop drawings and product data to the architect for review, the review resulting in approval, partial approval, notes, or rejection, with the architect sometimes rejecting the entire submittal or requesting resubmittal of some items, and notes the lead time between review and fabrication. Motivates CN03 as a reading of the reviewer's stated action and CN01's separation of substitution proposals from clarifications; motivation only, not evidence of Jev performance.

These sources motivate the design problem and its boundaries. They do not demonstrate Jev performance on this question.
