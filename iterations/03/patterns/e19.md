# E19: Classify cache freshness for a requested read

Use semantic source-change evidence to guide deterministic freshness checks rather than trust a cached answer after state changed.

## State contract

Supply a compact named JSON object with these required fields:

- <code>requested_read</code>
- <code>cache_metadata</code>
- <code>source_change_evidence</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>freshness_relation</code>.

~~~json
{
  "freshness_relation": {
    "type": "choice",
    "instructions": "What freshness relation is supported for requested_read by cache_metadata and source_change_evidence? Classify the stated semantic relation only. Do not compare clocks, calculate TTL expiry, read the cache, or assert current source truth.",
    "criteria": {
      "fresh_for_requested_read": "The supplied evidence explicitly ties the cached source revision or validated snapshot to the requested read with no stated intervening change.",
      "stale": "The supplied evidence explicitly shows a relevant source change after the cached snapshot.",
      "source_change_unverifiable": "The source change evidence is absent, ambiguous, or cannot be tied to the cached snapshot and requested read.",
      "not_a_cache_case": "The supplied state explicitly says no cached result is being considered for the requested read."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Use code to compare exact revisions and timestamps; refetch or review whenever current source identity cannot be proven.

**Code and governance own:** TTL arithmetic, cache keys, snapshots, refetching, invalidation, and any consumption of a cached result.

**Simpler baseline:** Reuse a cached result until its generic TTL expires.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike H16, which invalidates a pending action after a material observation, this evaluates whether a named cache snapshot remains tied to a requested read.

## Limits, source, and shared skill

Model output cannot prove a source revision, clock, or cache key.
