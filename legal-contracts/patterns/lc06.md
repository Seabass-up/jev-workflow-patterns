# LC06 — Defined term is used in the sense its definition gives

[Contracts catalog]({{ '/legal-contracts/' | relative_url }}) · [Evaluation and limitations]({{ '/legal-contracts/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/legal-contracts.md)

Check whether a passage uses a defined term in the sense the supplied definition gives it, in a different sense, or as an ordinary word.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/legal-contracts/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Catches drift between a definition and its uses before the lawyer reads the draft; code owns the exact matching of the term.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `defined_term`
- `definition_text`
- `usage_text`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 4 options, that floor is equivalent to a top probability of 0.85; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `LC06-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "defined_term": "Deliverables",
  "definition_text": "\"Deliverables\" means the reports, data models, and documentation that Northgate Supply creates specifically for Harbor Analytics under a Statement of Work. Deliverables do not include Northgate Supply's Pre-Existing Materials or any third-party software, whether or not incorporated into a report or model.",
  "usage_text": "Harbor Analytics shall pay the license fees for any third-party software included in the Deliverables within thirty days after receipt of Northgate Supply's invoice, and such fees are in addition to the fees stated in the applicable Statement of Work."
}
```

Expected label: `inconsistent_with_definition`.

The passage uses the capitalized defined term and treats third-party software as something the Deliverables can include, which the definition expressly excludes; the contract directs that a use of the defined term applied to something outside the definition is inconsistent, not an ordinary-sense use.

## Code-owned responsibilities

Code finds every occurrence of the term exactly, including capitalization, supplies each passage separately, and records the definition's clause number; the label never rewrites the definition or the usage.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One re-check with a longer passage around the same occurrence when the label is unknown.

## Verification recipe

Compare labels with a lawyer's definitions check on a set of reviewed drafts; review every use the lawyer marked that the label called consistent.

This describes required verification work, not checks already performed.

Motivates LC01 (confidentiality as a clause type), LC03 (reciprocal versus one-sided), LC06 (a defined term and its uses), LC07 (notice elements), and LC08 (carve-outs from a rule). Motivation, not evidence of Jev performance.
