# MK07 — Campaign brief states goal, audience, and metric

[Marketing catalog]({{ '/marketing/' | relative_url }}) · [Evaluation and limitations]({{ '/marketing/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/marketing.md)

Classify whether a campaign brief states the three elements a team requires before creative work starts: a goal, an audience, and a success metric.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/marketing/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Sends incomplete briefs back before creative time is spent, without judging whether the goal is right or the metric is achievable.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `brief_text`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 6 options, that floor is equivalent to a top probability of 0.8333; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `MK07-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "brief_text": "Campaign: Lantern & Vale spring launch, paid social plus the Ember newsletter, going live the first week of April. Goal: establish Lantern & Vale as the go-to source for refillable cleaning concentrates and drive first orders of the Starter Trio. Audience: TBD; creative to propose once we have seen concepts. Success: we will measure first-order conversion rate from the landing page and cost per first order, with targets to be set after two weeks of baseline data. Budget is approved."
}
```

Expected label: `missing_audience`.

The brief states a goal and names two measures, and the contract says a named measure is enough even without a target value, so the metric counts as present. The audience heading exists but its content is TBD, so the brief never says whom the campaign is meant to reach, and exactly one element is missing.

## Code-owned responsibilities

Code supplies the brief text as submitted with its revision, checks required form fields and dates exactly, returns any label other than complete to the requester with the named gap, and leaves the decision to proceed with an incomplete brief to the marketing lead.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One re-check after the requester resubmits the brief.

## Verification recipe

Compare labels with the intake reviewer's decisions on a quarter of submitted briefs; review every brief the label called complete that the reviewer returned.

This describes required verification work, not checks already performed.

## Source inspiration

Motivation for the design, not evidence of Jev performance.
