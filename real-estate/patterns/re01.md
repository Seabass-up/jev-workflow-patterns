# RE01 — Listing feature claim is supported by the property facts

[Real estate catalog]({{ '/real-estate/' | relative_url }}) · [Evaluation and limitations]({{ '/real-estate/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/real-estate.md)

Check whether one factual claim in draft listing copy is supported by, contradicted by, or absent from the brokerage's own property record.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/real-estate/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Catches a feature claim the record does not back before the listing is published, while the agent keeps the decision to edit the copy or the record.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `listing_claim`
- `property_facts`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 4 options, that floor is equivalent to a top probability of 0.85; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `RE01-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "listing_claim": "Attached two-car garage with an epoxy-coated floor.",
  "property_facts": "Garage: detached, two bays, 22 x 22 ft, concrete slab with epoxy coating applied 2023; door opener replaced 2021. Driveway: asphalt, resealed 2024. Lot: 0.31 acres, rear fenced."
}
```

Expected label: `contradicted`.

The record states the two-car count and the epoxy floor the claim asserts, but it states the garage is detached, which is inconsistent with 'attached'. The contract says that when the record both states and contradicts parts of a claim, contradicted wins over supported.

## Code-owned responsibilities

Code splits listing copy into single claims, supplies the property record with its revision, compares counts and measurements exactly, and holds the listing for the agent when a claim is contradicted or not in the facts. The label never approves copy for publication.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One re-check after the agent adds the missing fact to the record or edits the claim.

## Verification recipe

Compare labels with the listing coordinator's fact-check notes on published listings; review every claim the label called supported that was later corrected.

This describes required verification work, not checks already performed.
