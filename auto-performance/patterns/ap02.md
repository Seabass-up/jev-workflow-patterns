# AP02 — Stated use of the vehicle: track, street, show, or mixed

[Auto performance catalog]({{ '/auto-performance/' | relative_url }}) · [Evaluation and limitations]({{ '/auto-performance/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/auto-performance.md)

Classify how a customer says the vehicle will be used so the shop can match parts and setup to the stated use.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/auto-performance/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Makes the stated use explicit before parts are chosen, so a street-only car is not quoted a competition setup and a track car is not quoted show parts.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `request_text`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 5 options, that floor is equivalent to a top probability of 0.84; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `AP02-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "request_text": "It's a purpose-built autocross and hill-climb car that lives on a trailer; it isn't registered and never touches a public road. On off weekends I haul it to the local cars-and-coffee meet so people can look it over. Looking for a setup that suits that."
}
```

Expected label: `mixed`.

Autocross and hill-climb driving is track use and display at a meet is show use, so the text states two uses for the same vehicle. The street mention only rules street use out, which the contract says is not a stated use, so it neither adds a third use nor makes the label track.

## Code-owned responsibilities

Code records the stated use with the request, asks the customer to confirm it before quoting, and applies any sanctioning-body or road-use rules itself; the label is a reading of the customer's words, not a determination of what the vehicle may be used for.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One re-check after the service writer asks the customer how the car will be used when the label is unknown.

## Verification recipe

Compare labels with the use the customer confirmed at intake and with the setup the shop actually built.

This describes required verification work, not checks already performed.
