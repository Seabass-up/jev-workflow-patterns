# HA08 — Self-explanation states a mechanism or merely repeats a fact

[Human + AI catalog]({{ '/human-ai/' | relative_url }}) · [Evaluation and limitations]({{ '/human-ai/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/human-ai.md)

Separate a learner's stated why/how explanation from restating the observed result.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/human-ai/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Helps an AI tutor choose whether to ask for a causal link, without treating fluent paraphrase as demonstrated explanation.

This is a proposed benefit, not an observed human outcome. All fixtures on this page are synthetic. No study with people was conducted for this catalog, and the question must not be used to infer a person's traits, ability, diagnosis, or intent.

## Required named state

Supply the following named fields as the evidence packet:

- `learning_prompt`
- `reference_mechanism`
- `learner_response`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. Preserve the exact source revision. Any remaining insufficiency or ambiguity follows the question's `unknown` criteria; a model label cannot establish missing facts.

## Complete synthetic example

This is fixture `HA08-4`, from the **challenge** split. Its author received the question contract without the original design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "learning_prompt": "Explain why closing the switch makes the lamp light in the described circuit.",
  "reference_mechanism": "The battery, lamp and switch form a single circuit with no alternative path. Closing the switch completes the conducting path, allowing current through the lamp and making it light.",
  "learner_response": "Closing the switch makes the lamp light because the lamp lights whenever the switch is closed. An open switch is not the condition under which the lamp lights."
}
```

Expected label: `restatement_only`.

The response uses because and a negation but only repeats the switch-state and lamp-state association. It supplies no conducting-path or current mechanism and does not assert a conflicting mechanism.

## Code-owned responsibilities

An educator verifies the reference mechanism; code preserves the exact attempt and avoids translating one label into a grade or mastery score.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

Ask one why/how prompt targeting the missing link, or escalate conflicting mechanisms to a knowledgeable tutor.

## Verification recipe

Use separately labeled explanations including correct alternative mechanisms, partial explanations, parroting, and explicit contradictions; human review settles disputed cases.

This describes required verification work, not checks already performed. Separate agreement with synthetic expected labels from successful execution of the real workflow and from any measured benefit to a person.
