# H29: Numeric precision boundary controller

Keep semantic classification and exact arithmetic in their appropriate, separately tested components.

## State contract

Supply a compact named JSON object with these required fields:

- <code>requested_decision</code>
- <code>available_inputs</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>precision_route</code>.

~~~json
{
  "precision_route": {
    "type": "choice",
    "instructions": "What precision route is required by requested_decision and available_inputs? Classify the work shape only. Do not perform arithmetic, compare exact values, calculate a date, or silently round a number.",
    "criteria": {
      "semantic_judgment_only": "The requested decision is a bounded semantic classification directly supported by supplied text.",
      "semantic_then_deterministic_calculation": "The task first needs a semantic label or source selection, then exact arithmetic, date handling, or rule evaluation in code.",
      "deterministic_calculation_only": "The supplied inputs already define an exact calculation or comparison with no semantic judgment needed.",
      "insufficient": "The requested decision or inputs do not establish a safe route."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Use code for exact operations and retain the semantic input/result boundary for audit; route unclear work to review.

**Code and governance own:** All numeric parsing, arithmetic, rounding, time zones, date math, rules, and action.

**Simpler baseline:** Ask a language model to calculate from prose.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike H13's date-expression projection, this is a cross-domain boundary controller for any task that mixes semantic interpretation with exact calculation.

## Limits, source, and shared skill

It cannot validate an implementation's numerical correctness; deterministic code still needs tests.
