# E22: Classify extractor field source-support diagnosis

Detect whether an extractor's proposed field is tied to the intended source evidence before downstream use.

## State contract

Supply a compact named JSON object with these required fields:

- <code>source_document</code>
- <code>proposed_field</code>
- <code>candidate_spans</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>source_support</code>.

~~~json
{
  "source_support": {
"type": "choice",
"instructions": "How does proposed_field relate to source_document and the code-found candidate_spans? Judge source support for this one field. Do not normalize a value, calculate, repair JSON, or accept an extraction.",
"criteria": {
  "verbatim_supported": "The proposed field matches an appropriate candidate span that directly states the requested field value.",
  "source_absent": "The requested field value is not stated by the supplied source/candidates.",
  "unrelated_source_span": "The proposed value appears in the source but belongs to a different labeled fact or context than the requested field.",
  "ambiguous_candidates": "More than one supplied candidate plausibly fits or the source cannot establish one listed relation."
}
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Escalate absent, unrelated, ambiguous, or uncertain fields to the extraction-review path and retain source/span bindings.

**Code and governance own:** Candidate discovery, string equality, schema validation, type conversion, data writes, and escalation execution.

**Simpler baseline:** Manually compare every extractor field to its source document.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L03's value meaning/entity check and H14's offset provenance, this is a verifier rung for one extractor field after code has supplied candidate spans.

## Limits and source

It cannot prove the source is authoritative or that a supported value is valid for the destination system.
