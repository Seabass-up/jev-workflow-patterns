# SE04 — Meta description summarizes the page or withholds its point

[SEO catalog]({{ '/seo/' | relative_url }}) · [Evaluation and limitations]({{ '/seo/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/seo.md)

Classify whether a meta description summarizes what the page contains, teases or overpromises, is site-wide boilerplate, or describes a different topic.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/seo/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Reviews descriptions across a site for teasing or mismatched text in one pass, so editors rewrite only the ones flagged.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `meta_description`
- `page_summary`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 5 options, that floor is equivalent to a top probability of 0.84; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `SE04-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "meta_description": "Brightloom: kitchen tools built to outlast trends. Most people are making one silent mistake that is quietly ruining their kettle, and the fix takes under a minute. Find out what it is inside.",
  "page_summary": "Main heading: How to descale your kettle. The opening content says limescale builds up from hard water, explains that it slows boiling and leaves flakes in drinks, and then gives a step-by-step vinegar soak with rinse instructions."
}
```

Expected label: `teases_or_overpromises`.

The first sentence is a site tagline, but the contract says a description that combines a generic tagline with a page-specific sentence is judged by the page-specific sentence; that sentence is about the page's subject yet withholds the point (limescale) and uses secrecy wording to draw a click, which is teases_or_overpromises rather than generic_or_boilerplate.

## Code-owned responsibilities

Code extracts the description and summary, measures length and duplicates exactly, and queues flagged pages; the editor decides the rewrite, and any claim in a description is substantiated by people.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One re-check with a longer page summary when the label is unknown.

## Verification recipe

Compare labels with an editor's review of a sample of descriptions per template; review every summarizes_page label on a description the editor flagged as a tease.

This describes required verification work, not checks already performed.

## Source inspiration

- [Google Search Central: How to Write Meta Descriptions](https://developers.google.com/search/docs/appearance/snippet) (SE-S3). Explains that a meta description should accurately summarize the page and be specific to it rather than generic or a list of keywords. Motivates SE04 as a comparison of a description with a page summary, with separate labels for teasing, boilerplate, and mismatch; motivation only, not evidence of Jev performance.
- [Google Search Central: Creating Helpful, Reliable, People-First Content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content) (SE-S5). A self-assessment list asking whether a headline or title summarizes the content without exaggeration, whether a site has a primary purpose or focus, whether content substantially changed rather than only its date, and whether the content answers the questions it raises. Motivates SE02, SE04, SE06, SE07, and SE08 as readings of page text; the questions are motivation for the patterns, not evidence of Jev performance.

These sources motivate the design problem and its boundaries. They do not demonstrate Jev performance on this question.
