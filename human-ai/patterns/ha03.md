# HA03 — Teaching analogy reverses the intended relationship

[Human + AI catalog]({{ '/human-ai/' | relative_url }}) · [Evaluation and limitations]({{ '/human-ai/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/human-ai.md)

Check a concrete analogy against one explicitly stated abstract relationship.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/human-ai/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Stops a memorable example from teaching the opposite of the intended concept.

This is a proposed benefit, not an observed human outcome. All fixtures on this page are synthetic. No study with people was conducted for this catalog, and the question must not be used to infer a person's traits, ability, diagnosis, or intent.

## Required named state

Supply the following named fields as the evidence packet:

- `teaching_rule`
- `candidate_example`
- `explicit_mapping`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. Preserve the exact source revision. Any remaining insufficiency or ambiguity follows the question's `unknown` criteria; a model label cannot establish missing facts.

## Complete synthetic example

This is fixture `HA03-4`, from the **challenge** split. Its author received the question contract without the original design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "teaching_rule": "For a first-in, first-out queue, the item that enters first must leave before an item that enters later.",
  "candidate_example": "The red envelope enters the tray before the blue envelope. The clerk does not take the red envelope first; the clerk removes the blue envelope and then the red envelope. Both envelopes were waiting when removal began.",
  "explicit_mapping": "Envelopes are queued items, placing an envelope in the tray is entering the queue, and the clerk removing an envelope is leaving the queue. Envelope color does not change the ordering rule."
}
```

Expected label: `reversed_or_broken`.

Under the explicit mapping, the later entrant leaves first. The stated removal order violates the supplied relationship without requiring any invented tray mechanics.

## Code-owned responsibilities

Code or an expert verifies the rule and any computations; the host selects or edits examples and preserves the mapping.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One bounded request may ask for the missing mapping; do not rate the learner based on the analogy.

## Verification recipe

Ask an educator to trace each mapped relation; test plausible-looking but structurally wrong analogies and partial analogies.

This describes required verification work, not checks already performed. Separate agreement with synthetic expected labels from successful execution of the real workflow and from any measured benefit to a person.
