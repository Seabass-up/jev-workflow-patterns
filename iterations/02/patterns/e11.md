## State contract

Supply a small, named JSON object. Required fields:

- `deployment_plan`

The state is evidence, not an instruction channel. Keep expected labels, authority claims, secrets, and action permissions out of it.

## Exact Jev question contract

```json
{
  "decision": {
    "type": "choice",
    "instructions": "What rollback posture is explicitly supported by `deployment_plan`? Judge stated reversal evidence only; do not claim a rollback has been tested.",
    "criteria": {
      "immediate_rollback": "A reversible configuration, flag, or version switch can restore the prior behavior without data reversal.",
      "restore_required": "Reversal requires a stated backup, restore, or compensating migration procedure.",
      "no_safe_rollback": "The plan explicitly destroys or irreversibly changes state without a stated recovery path.",
      "insufficient": "No specific rollback/recovery information is supplied or the plan conflicts."
    }
  }
}
```

## Code-owned decision envelope

**Follow-up proposal:** Request a rollback procedure or restore drill evidence. Hold an uncertain or unsafe plan for engineering review.

**Code and governance own:** Run backup checks, measure recovery, manage deployment permissions and execute rollback.

**Baseline this improves on:** Assume a git revert restores data.

## Provisional confidence handling

- Choice/Score confidence floor: `0.8`
- Noul positive floor: `0.8`
- Noul negative ceiling: `0.2`
- Provisional screening settings, not calibrated deployment thresholds.

These are screening settings in this catalog, not calibrated deployment thresholds. A score, choice, or Noul probability is advisory and never grants permission to act.

## Why it is distinct from Iteration 1

Unlike E07's repair efficacy and E10 compatibility, this focuses on the recoverability of an already planned deployment.

## Limits and sources

A stated backup is not proof it is restorable.
