# L24: Classify semantic feature-question validity

Reject feature questions that leak the target, duplicate existing signals, or cannot be observed from permitted text.

**Contract version 2:** Use underspecified only when essential facts prevent judgment; otherwise target leakage takes precedence over feature redundancy. The current cases cover all answer labels; see the evaluation record for synthetic results. This is not production qualification.

## State contract

Supply a compact named JSON object with these required fields:

- <code>feature_question</code>
- <code>target_definition</code>
- <code>available_evidence</code>
- <code>existing_features</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>feature_quality</code>.

~~~json
{
  "feature_quality": {
    "type": "choice",
    "instructions": "Judge feature_question for target_definition using available_evidence and existing_features. Apply this order: underspecified only when essential information is missing such that the question cannot be judged; otherwise target_leaking for direct or reliable exposure of the target/outcome; otherwise redundant for substantial duplication without a distinct measurement purpose; otherwise observable_nonleaking. Do not train a model, inspect unshown held-out labels, or claim predictive value.",
    "criteria": {
      "observable_nonleaking": "The feature can be answered from permitted evidence, does not directly or reliably reveal the target/outcome, and is not substantially duplicated by a named existing feature.",
      "redundant": "The feature substantially duplicates a named existing feature without a stated distinct measurement purpose, and does not directly/reliably expose the target.",
      "target_leaking": "The feature directly asks for, restates, or reliably exposes the target/outcome that a later model is meant to predict, even if it also duplicates another feature.",
      "underspecified": "Essential information about the question, target, permitted evidence, or existing features is missing such that no specific validity defect or safe observability can be established."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Hold non-observable, redundant, or leaking candidates; evaluate accepted questions only with versioned features and held-out outcomes.

**Code and governance own:** Dataset construction, label access, training, feature selection, metrics, deployment, and decisions based on predictions.

**Simpler baseline:** Let an LLM propose and train every textual feature without a preflight review.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L06's proposed memory-update category and H20's human-adjudication ledger, this is a pre-training feature-contract review that explicitly isolates leakage and redundancy.

## Limits and source

A non-leaking label does not prove usefulness, fairness, causal validity, or model performance.
