# LR05 — Reschedule request proposes a time, defers, or cancels

[Logistics routing catalog]({{ '/logistics-routing/' | relative_url }}) · [Evaluation and limitations]({{ '/logistics-routing/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/logistics-routing.md)

Classify whether a customer's reschedule message names a new time, asks the company to choose, or cancels the visit.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/logistics-routing/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Starts the right flow, confirmation, options, or cancellation, from the message itself while the calendar and availability stay in code.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Complete synthetic example

This is fixture `LR05-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "reschedule_message": "Please scrap Friday's delivery slot, we won't have the floor cleared in time. Just send over whatever openings you have and I will pick one that works."
}
```

Expected label: `defers_to_company`.

The message cancels the planned visit but asks for a new one, so cancels_visit does not apply. Because it asks the company to offer options and names no day, time, or window, the contract's rule for a cancelled-but-replaced visit selects defers_to_company.

## Code-owned responsibilities

Code copies the proposed expression verbatim, resolves it against the calendar, checks route availability, and sends the confirmation, the options, or the cancellation notice; the label only chooses which flow starts.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One re-check after the customer replies to a clarification when the label is unknown.

## Verification recipe

Compare labels with the action a dispatcher took on the same messages; measure cancellations the label read as reschedules first.

This describes required verification work, not checks already performed.
