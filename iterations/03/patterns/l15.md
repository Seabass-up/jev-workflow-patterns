# L15: Detect a hard-wrapped sentence continuation

Recover a text preprocessing relation while preserving source characters in code.

## State contract

Supply a compact named JSON object with these required fields:

- <code>previous_line</code>
- <code>next_line</code>
- <code>has_blank_gap</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>continues_sentence</code>.

~~~json
{
  "continues_sentence": {
    "type": "noul",
    "instructions": "Does next_line continue a sentence left unfinished at the end of previous_line? A blank gap, a new heading, a list item, or a complete previous sentence weighs against continuation. Judge only this adjacent textual relation.",
    "criteria": {
      "true": "The next line picks up the same sentence broken by formatting.",
      "false": "The next line begins a new sentence, item, heading, or thought."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Use the probability with deterministic punctuation and blank-gap rules; preserve the original line provenance whether code stitches or separates it.

**Code and governance own:** Line splitting, explicit-marker detection, character-preserving joins, output rendering, and source offsets.

**Simpler baseline:** Pass raw hard-wrapped text to an answer model or rewrite it generatively.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L09's malformed-output failure taxonomy, this is a narrow source-text adjacency judgment used before LLM context assembly.

## Limits, source, and shared skill

Ambiguous prose, poetry, tables, and languages with different punctuation conventions need domain evaluation.
