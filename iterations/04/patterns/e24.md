# E24: Classify test-double behavioral fidelity gap

Surface whether a mock removes a behavior material to the test's claimed conclusion.

## State contract

Supply a compact named JSON object with these required fields:

- <code>dependency_contract</code>
- <code>test_double</code>
- <code>test_claim</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>fidelity</code>.

~~~json
{
  "fidelity": {
"type": "choice",
"instructions": "How does test_double compare with the relevant behavior in dependency_contract for test_claim? Judge only the described behavioral fidelity. Do not execute tests, infer unshown callers, or declare production behavior.",
"criteria": {
  "behaviorally_equivalent": "The double preserves the contract behavior relevant to the stated test claim, including the named result/failure semantics.",
  "safely_simplified": "The double omits irrelevant detail but retains the behavior needed for the stated test claim.",
  "missing_relevant_failure_or_side_effect": "The double omits or changes a failure path, ordering rule, state effect, or side effect material to the stated claim.",
  "insufficient": "The contract, double, or claim does not show enough behavior to classify."
}
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Inspect the named double and contract path; add a deterministic integration or contract test where needed.

**Code and governance own:** Test execution, contract interpretation, mock implementation, coverage measurement, and release decisions.

**Simpler baseline:** Review every test double manually against its real dependency contract.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike E02's requirement-coverage check and E08's reproducibility evidence, this compares a substitute dependency behavior to the contract a test relies on.

## Limits and source

It cannot prove the real dependency works or that all unshown callers behave compatibly.
