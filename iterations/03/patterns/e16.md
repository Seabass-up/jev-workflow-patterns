# E16: Classify configuration override precedence

Interpret stated precedence language before code resolves actual configuration values.

## State contract

Supply a compact named JSON object with these required fields:

- <code>base_configuration</code>
- <code>override_configuration</code>
- <code>precedence_rule</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>precedence</code>.

~~~json
{
  "precedence": {
    "type": "choice",
    "instructions": "How does precedence_rule say base_configuration and override_configuration apply to the named setting? Classify the stated precedence only. When the state gives incompatible values and says both must control without a stated resolution, choose explicit_conflict rather than insufficient. Do not calculate a value, assume conventional precedence, or deploy a configuration.",
    "criteria": {
      "override_controls": "The stated rule explicitly makes the supplied override control the named setting in this context.",
      "base_controls": "The stated rule explicitly keeps the base value controlling despite the supplied override.",
      "explicit_conflict": "The supplied texts explicitly impose incompatible controlling values without a stated resolution.",
      "insufficient": "The rule or configurations do not establish a controlling relation for the named setting."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Resolve conflicts with the configuration owner and use a deterministic resolver against a versioned snapshot.

**Code and governance own:** Parsing, precedence implementation, exact values, secrets, deployment, and runtime verification.

**Simpler baseline:** Assume last textual assignment wins.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike E10 schema-rollout compatibility, this is a named-setting precedence judgment between configuration layers.

## Limits, source, and shared skill

It cannot safely read secrets or establish deployed runtime state.
