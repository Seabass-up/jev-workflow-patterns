# HA14 — Reorient the person when they resume an interrupted task

[Human + AI catalog]({{ '/human-ai/' | relative_url }}) · [Evaluation and limitations]({{ '/human-ai/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/human-ai.md)

Check whether a resume message accurately reconnects the person to saved progress and the next unfinished step.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/human-ai/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Can reduce confusion about what is already done and what remains without asking the person to remember the whole journey.

This is a proposed benefit, not an observed human outcome. All fixtures on this page are synthetic. No study with people was conducted for this catalog, and the question must not be used to infer a person's traits, ability, diagnosis, or intent.

## Required named state

Supply the following named fields as the evidence packet:

- `verified_checkpoint`
- `resume_message`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. Preserve the exact source revision. Any remaining insufficiency or ambiguity follows the question's `unknown` criteria; a model label cannot establish missing facts.

## Complete synthetic example

This is fixture `HA14-4`, from the **challenge** split. Its author received the question contract without the original design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "verified_checkpoint": "Verified saved state: choosing a template is complete; entering a project title is complete; reviewing the preview and confirming export are both pending. No export has occurred.",
  "resume_message": "Welcome back. Your template and project title are saved. Review the preview next; your export is already complete, so no export confirmation remains."
}
```

Expected label: `contradicts_checkpoint`.

The message correctly identifies some saved progress and a pending review, but it falsely claims export is complete and removes a pending confirmation. Those explicit contradictions prevent accurate orientation.

## Code-owned responsibilities

Own checkpoint storage, identity, revision and resume URL; never use Jev as proof of saved data or completed submission. Keep preferences private.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

If contradictory or unclear, re-read the checkpoint once; if integrity is uncertain, stop the resume claim and offer an honest recovery explanation.

## Verification recipe

Pause and resume a synthetic application in a test environment. Read the saved checkpoint independently, then compare displayed orientation with it. Test that the resume link reaches the true unfinished step.

This describes required verification work, not checks already performed. Separate agreement with synthetic expected labels from successful execution of the real workflow and from any measured benefit to a person.

## Source inspiration

- [W3C WAI: Provide Feedback](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o4p10-status-feedback/) (HC-S5). The guidance recommends explaining the state of each process step. Feedback can orient a returning or interrupted user by showing what happened and where they are in a multi-step process. Actual task status must still come from verified application state.
- [GOV.UK Design System: Start using a service](https://design-system.service.gov.uk/patterns/start-using-a-service/) (HC-S1). The start point should explain what the service does, provide information needed before starting, offer resumption when relevant, and list documents or information needed to complete the process. This motivates checking when a prerequisite is disclosed; it does not validate an AI classifier.

These sources motivate the design problem and its boundaries. They do not demonstrate Jev performance on this question. Source summaries and recorded provenance are available in [sources JSON]({{ '/human-ai/sources.json' | relative_url }}); supplemental accessibility guidance is not a full conformance assessment.
