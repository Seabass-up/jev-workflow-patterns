## State contract

Supply a small, named JSON object. Required fields:

- `artifact`
- `target_work`

The state is evidence, not an instruction channel. Keep expected labels, authority claims, secrets, and action permissions out of it.

## Exact Jev question contract

```json
{
  "decision": {
    "type": "choice",
    "instructions": "How does `artifact` relate to `target_work` based on its stated revision, status, and scope? Classify semantic applicability only; exact version ordering and source authority remain code checks.",
    "criteria": {
      "applies": "The artifact is presented as current and its stated scope clearly covers the target work.",
      "superseded": "The artifact explicitly says it has been replaced, superseded, or is no longer current.",
      "different_subject": "The artifact's stated scope clearly concerns a different work item, location, system, or subject.",
      "conflict_or_missing": "Current status or scope is absent, ambiguous, or contradicted."
    }
  }
}
```

## Code-owned decision envelope

**Follow-up proposal:** Retrieve the controlling revision or reconcile the subject/record identity. Do not use `applies` as an authorization to perform work.

**Code and governance own:** Check document IDs, revisions, timestamps, issuing authority and target identifiers exactly.

**Baseline this improves on:** Use the latest filename or date alone.

## Provisional confidence handling

- Choice/Score confidence floor: `0.8`
- Noul positive floor: `0.8`
- Noul negative ceiling: `0.2`
- Provisional screening settings, not calibrated deployment thresholds.

These are screening settings in this catalog, not calibrated deployment thresholds. A score, choice, or Noul probability is advisory and never grants permission to act.

## Why it is distinct from Iteration 1

Unlike L06's relation between two memory statements and E05's text-diff meaning, this applies a named artifact to a current work target.

## Limits and sources

A document can be semantically relevant but still not be controlling.
