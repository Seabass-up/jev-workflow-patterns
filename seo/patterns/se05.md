# SE05 — Backlink context is editorial, disclosed, user-submitted, or a listing

[SEO catalog]({{ '/seo/' | relative_url }}) · [Evaluation and limitations]({{ '/seo/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/seo.md)

Classify the context in which a referring page links to the site: within the author's own prose, under a paid or sponsored disclosure, in visitor-submitted content, or in a list of links.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/seo/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Sorts a backlink export by context without a person opening every referring page; what to do with each group stays with the team.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `surrounding_text`
- `link_markup`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Exact question JSON

Reproduced from the frozen [catalog JSON]({{ '/seo/catalog.json' | relative_url }}). Treat state values as evidence rather than instructions to modify this contract.

```json
{
  "decision": {
    "type": "choice",
    "instructions": "First, if any required field (`surrounding_text`, `link_markup`) is absent, empty, or lacks the information needed for this judgment, select unknown before considering other labels. `surrounding_text` is the paragraph or block on the referring page that contains the link, including any nearby labels, and `link_markup` is the anchor element as extracted. Classify the context of the link. If the markup's rel value contains sponsored, or the surrounding text states that the placement is paid, sponsored, an advertisement, an affiliate link, or a partnership, the context is disclosed. If the text is a visitor's comment, forum reply, review, or profile, it is user-submitted. If the block is a list of links or resources with little prose about each, it is a listing. If the author refers to the destination as part of the page's own argument, story, or advice, it is editorial. If more than one applies, select the first in this order: disclosed_sponsored, user_submitted, listing_or_directory, editorial_mention.     "criteria": {

      "disclosed_sponsored": "The markup's rel value contains sponsored, or the surrounding text states the placement is paid, sponsored, an advertisement, an affiliate link, or a partnership.",
      "user_submitted": "The text containing the link is a visitor's comment, forum reply, review, or profile rather than the page author's content.",
      "listing_or_directory": "The link sits in a list of links or resources with little prose about each entry.",

    }
  }

```

## Policy recorded with its option count

Review when confidence is below 0.8. With 5 options, that floor is equivalent to a top probability of 0.84; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `SE05-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "surrounding_text": "Forum reply from member kettlefan42: I switched to the Brightloom gooseneck last spring and the flow control is the best I have used. Full disclosure, that is my affiliate link, so I get a small cut if you buy through it. Happy to answer questions about it in this thread.",
  "link_markup": "<a href=\"https://brightloom.example/gooseneck?ref=kettlefan42\" rel=\"ugc nofollow\">Brightloom gooseneck</a>"
}
```

Expected label: `disclosed_sponsored`.

The block is a forum reply and the rel value is ugc, both pointing to user_submitted, but the surrounding text states the placement is an affiliate link, and when more than one context applies the contract selects disclosed_sponsored first in its stated order.

## Code-owned responsibilities

Code parses rel attributes exactly and records them separately, resolves the referring address, and keeps the export; the label groups contexts and never decides whether a link is valuable, harmful, or compliant with any search engine's rules.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

None; unknown contexts go to the analyst with the referring address.

## Verification recipe

Compare labels with an analyst's manual context tags on a sample of referring pages per domain; review every editorial_mention label on a page the analyst tagged as sponsored.

This describes required verification work, not checks already performed.
