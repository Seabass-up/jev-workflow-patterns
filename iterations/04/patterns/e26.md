# E26: Classify semantic lint enforcement tier

Choose a safe enforcement shape for a rule instead of pretending every guideline is deterministically lintable.

## State contract

Supply a compact named JSON object with these required fields:

- <code>engineering_rule</code>
- <code>candidate_check</code>
- <code>enforcement_context</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>enforcement_tier</code>.

~~~json
{
  "enforcement_tier": {
"type": "choice",
"instructions": "What enforcement tier fits engineering_rule and candidate_check under enforcement_context? Choose the narrowest safe tier. Do not turn a recommendation into a CI failure, modify code, or claim the rule is universally valid.",
"criteria": {
  "deterministic_check": "The rule can be evaluated from explicit syntax, types, or fixed data with ordinary code alone.",
  "jev_advisory_plus_code_gate": "The rule needs semantic interpretation, but code can bind scope, preserve evidence, and route an advisory result for review.",
  "human_review_only": "The rule depends on broad design intent, unshown context, or consequence judgment that should not be automated into a gate.",
  "underspecified": "The supplied rule/check context lacks a clear condition or acceptance boundary."
}
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Draft deterministic checks where possible; retain Jev outputs as advisory evidence and ask a rule owner to define underspecified rules.

**Code and governance own:** CI configuration, pass/fail policy, code modifications, permissions, and release decisions.

**Simpler baseline:** Treat every engineering guideline as human review regardless of its formalizability.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike E05's change-type classification and H05's repair of a demonstrated question defect, this decides the appropriate enforcement architecture for a proposed semantic lint.

## Limits and source

A tier recommendation is not an authorization to fail builds or a proof that a rule is correct.
