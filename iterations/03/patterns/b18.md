# B18: Classify a project-plan predecessor relation

Identify whether a named task is semantically blocked by a named project predecessor.

## State contract

Supply a compact named JSON object with these required fields:

- <code>requested_task</code>
- <code>project_plan</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>predecessor_relation</code>.

~~~json
{
  "predecessor_relation": {
    "type": "choice",
    "instructions": "How does requested_task relate to the stated project_plan? Determine only whether a named predecessor blocks the described task. Do not schedule work, infer capacity, interpret a contract, or treat a desired sequence as a completed prerequisite.",
    "criteria": {
      "unblocked": "The plan explicitly states the task may proceed now or its named prerequisite is explicitly complete.",
      "waits_on_predecessor": "The plan explicitly makes the task depend on a named predecessor that is not shown complete.",
      "unrelated_to_named_predecessor": "The plan explicitly shows the named predecessor does not govern the requested task.",
      "insufficient": "The plan does not clearly establish a relevant dependency and status."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Ask the plan owner for the missing dependency or verified completion evidence before schedule changes.

**Code and governance own:** Calendar, resource allocation, work authorization, sequencing, and actual status changes.

**Simpler baseline:** Escalate every project task relationship to a planner.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike E12's precondition coverage of a runbook step, this classifies a business project-plan dependency and does not judge the correctness of an operational action.

## Limits, source, and shared skill

A plan can be stale or incomplete; no output authorizes work.
