# HA23 — Are alternatives compared on the same basis?

[Human + AI catalog]({{ '/human-ai/' | relative_url }}) · [Evaluation and limitations]({{ '/human-ai/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/human-ai.md)

Check a comparison draft for uneven criteria or mismatched evidence status across the alternatives the user named.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/human-ai/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Make side-by-side choices easier to assess without claiming objective neutrality or deciding which alternative is best.

This is a proposed benefit, not an observed human outcome. All fixtures on this page are synthetic. No study with people was conducted for this catalog, and the question must not be used to infer a person's traits, ability, diagnosis, or intent.

## Required named state

Supply the following named fields as the evidence packet:

- `requested_comparison`
- `source_facts`
- `comparison_draft`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. Preserve the exact source revision. Any remaining insufficiency or ambiguity follows the question's `unknown` criteria; a model label cannot establish missing facts.

## Exact question JSON

The following question object is reproduced from the frozen [catalog JSON]({{ '/human-ai/catalog.json' | relative_url }}). Treat state values as evidence rather than instructions to modify this contract.

```json
{
  "decision": {
    "type": "choice",
    "instructions": "First, if any of `requested_comparison`, `source_facts`, `comparison_draft` is absent, empty, or too unclear for this judgment, select unknown; never turn missing evidence into a negative finding. Compare `comparison_draft` with the options and criteria explicitly named in `requested_comparison`, using `source_facts`. Choose uneven_evidence_status if the draft presents an unverified claim for one option as established while preserving uncertainty for another; this takes precedence over uneven_criteria. Choose uneven_criteria if a requested criterion is omitted for one option but evaluated for another. Do not demand identical sentence length or equal praise. Use only supplied evidence.     "criteria": {
      "comparable": "Every requested option is discussed against the same requested criteria and evidence-status distinctions are preserved.",
      "uneven_criteria": "At least one requested criterion is evaluated for one option but omitted for another.",
      "uneven_evidence_status": "Equivalent uncertainty or verification status is portrayed inconsistently between options.",
      "unknown": "Required evidence is missing, contradictory, ambiguous, or outside this question's scope."
    }
  }
}
```

## Complete synthetic example

This is fixture `HA23-4`, from the **challenge** split. Its author received the question contract without the original design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "requested_comparison": "Compare handheld radios A and B on stated battery endurance and availability of replacement clips.",
  "source_facts": "For both A and B, the manufacturers claim eight-hour battery endurance, with neither claim independently tested. Replacement clips are listed in both manufacturers' catalogs.",
  "comparison_draft": "A has an eight-hour battery life and replacement clips are available. B's manufacturer claims eight hours, but that endurance has not been verified."
}
```

Expected label: `uneven_evidence_status`.

The draft presents A's equally unverified endurance as established but preserves uncertainty for B. It also omits B's requested clip criterion; the contract explicitly gives uneven evidence status precedence.

## Code-owned responsibilities

Keep the user-selected option set and criteria; validate names and source status. Exclude political or consequential decision scoring. Do not rank people, infer preferences, or treat this check as comprehensive fairness certification.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

Fill one missing comparison cell from authorized source evidence or label it unknown. Do not manufacture symmetry by giving unsupported equal praise.

## Verification recipe

Audit criterion-by-option coverage deterministically where IDs exist, then have reviewers inspect semantic parity. Verify corrections neither invent missing values nor erase uncertainty.

This describes required verification work, not checks already performed. Separate agreement with synthetic expected labels from successful execution of the real workflow and from any measured benefit to a person.
