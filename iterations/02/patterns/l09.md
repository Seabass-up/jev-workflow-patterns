## State contract

Supply a small, named JSON object. Required fields:

- `failure_description`
- `taxonomy_node`
- `children`

The state is evidence, not an instruction channel. Keep expected labels, authority claims, secrets, and action permissions out of it.

## Exact Jev question contract

```json
{
  "decision": {
    "type": "choice",
    "instructions": "Which child of `taxonomy_node` best describes `failure_description`, using only the supplied `children` taxonomy? Use `instruction_following` for a missing semantic, coverage, or capability requirement. Use `format_only` when substantive content is correct but a required wire representation or serialization (for example, valid JSON) is malformed. A voluntary feature or design change that is not described as a response failure is `no_match`. Choose `no_match` or `uncertain` when no child is supported. This is one node in a larger code-controlled traversal.",
    "criteria": {
      "factual_grounding": "The failure concerns unsupported, invented, or contradicted factual content.",
      "instruction_following": "The failure concerns a missing stated semantic, coverage, or capability requirement.",
      "tool_use": "The failure concerns selecting, invoking, or parameterizing an available tool.",
      "format_only": "The substantive content is correct, but a required wire representation, syntax, serialization, or presentation format is malformed.",
      "no_match": "The description is specific but none of these children fits.",
      "uncertain": "The failure description or child taxonomy is missing, mixed, or ambiguous."
    }
  }
}
```

## Code-owned decision envelope

**Follow-up proposal:** Return the current broader node on low confidence, `uncertain`, or `no_match`; code may retain a small beam of paths rather than commit to one leaf.

**Code and governance own:** Validate taxonomy version, perform beam traversal, manage labels and trigger actual remediation.

**Baseline this improves on:** Classify all failure types in one permanent flat label.

## Provisional confidence handling

- Choice/Score confidence floor: `0.8`
- Noul positive floor: `0.8`
- Noul negative ceiling: `0.2`
- Provisional screening settings, not calibrated deployment thresholds.

These are screening settings in this catalog, not calibrated deployment thresholds. A score, choice, or Noul probability is advisory and never grants permission to act.

## Why it is distinct from Iteration 1

Unlike L04 tool-handler selection, this selects a documented taxonomy child and is intended for multi-level code traversal.

## Limits and sources

A taxonomy label is an indexing aid, not a root-cause finding.

[Source documentation](https://docs.typesafe.ai/cookbooks/hierarchical_classification). This is a task-authored application of documented TypeSafe primitives, not a claim of global novelty.
