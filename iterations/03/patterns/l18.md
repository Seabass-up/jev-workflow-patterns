# L18: Classify System One decision depth

Route tasks needing multistep reasoning or exact computation away from a narrow Jev-only judgment.

## State contract

Supply a compact named JSON object with these required fields:

- <code>task_description</code>
- <code>available_state</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>decision_depth</code>.

~~~json
{
  "decision_depth": {
    "type": "choice",
    "instructions": "What decision depth is required by task_description using available_state? Classify the requested work, not the answer. Do not perform calculations, fill missing evidence, or claim that a System One model is sufficient for a consequential action.",
    "criteria": {
      "direct_stated_judgment": "The task asks for one focused semantic judgment directly supported by the supplied state.",
      "single_bounded_comparison": "The task asks for one comparison among supplied records, candidates, or criteria without a chain of derived steps.",
      "multistep_or_indirect_derivation": "The task requires chained reasoning, external retrieval, numeric precision, or a derived result beyond one bounded judgment.",
      "insufficient": "The task or available state does not establish the required decision shape."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Route multistep_or_indirect_derivation to a reasoning/retrieval workflow or review, preserving the task and missing-evidence explanation.

**Code and governance own:** Task decomposition, calculations, retrieval, permissions, thresholds, and action selection.

**Simpler baseline:** Send every natural-language request to one model call.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L04, which picks an offered handler for a request, this categorizes the semantic depth and known limitations of a task before any handler choice.

## Limits, source, and shared skill

It is an advisory routing aid, not a benchmark or a proof that another model will solve the task.
