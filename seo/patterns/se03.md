# SE03 — Internal link anchor text describes its destination

[SEO catalog]({{ '/seo/' | relative_url }}) · [Evaluation and limitations]({{ '/seo/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/seo.md)

Classify whether the anchor text of an internal link tells the reader what the destination page is about.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/seo/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Surfaces generic and misleading anchors across a site's internal links so they can be fixed in bulk; which links to change stays with the team.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `anchor_text`
- `destination_summary`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Exact question JSON

Anchor text that is only a call to action or a placeholder, such as click here, read more, this page, learn more, or a bare web address, with no word about the destination's subject, is generic.       "misleading_anchor": "The anchor names a subject, and that subject is different from the destination's subject.",

## Policy recorded with its option count

Review when confidence is below 0.8. With 4 options, that floor is equivalent to a top probability of 0.85; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `SE03-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "anchor_text": "file a Brightloom kettle warranty claim",
  "destination_summary": "Main heading: How to descale your Brightloom kettle. The page walks through removing limescale with vinegar or citric acid, how often to descale, and how to rinse the kettle afterward. It does not mention warranties, returns, or claims."
}
```

Expected label: `misleading_anchor`.

The anchor is not generic because it names a subject, and that subject, a warranty claim, is neither the destination's subject of descaling nor a broader or narrower topic that includes it; sharing the product name does not make the subjects the same, so the anchor is misleading.

## Code-owned responsibilities

Code crawls the links, extracts anchor text and destination summaries, counts generic anchors per template, and resolves redirects exactly; the label never changes a link.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

None; a link with an unknown label goes to the review list with its destination address.

## Verification recipe

Compare labels with a content editor's review of a sample of internal links per template; review every describes_destination label on an anchor the editor called generic.

This describes required verification work, not checks already performed.
