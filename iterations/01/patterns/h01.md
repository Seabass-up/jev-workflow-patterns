## The useful decision

Avoid interrupting the user when unresolved meaning cannot change the next permitted evidence-gathering step. Measure: Reject if it causes more wrong-target reads or does not reduce clarification turns against always-clarify on ambiguous tasks.

Required state fields: `request`, `interpretation_a`, `interpretation_b`. One request evaluates one coherent state. These questions are independent; none can see another answer in its batch.

## Consume the JSON and drill down

Host/code first establishes the task target from actual user context and verifies that the interpretation set is complete. Jev judges the two interpretations independently. Code compares the exact registered next-read operation and arguments for every non-ruled-out interpretation. Continue only if all are identical, read-only and already authorized; otherwise clarify. Writes never use this shortcut.

Follow-up: Ask which interpretation is intended when next reads diverge or candidate coverage is incomplete.

Code owns: Candidate completeness review, stable tool and argument identity, freshness, read-only status, access scope and permission. No Jev score grants permission.

Use provisional Choice/Score confidence ≥ 0.8 and Noul ≤ 0.2 / ≥ 0.8 only as experimental review gates. A Noul near 0.5 is uncertainty, not medium intensity. Thresholds require domain-specific evaluation. Provider failure, invalid output, stale state or missing required evidence goes to review, not to an assumed default. Gate only the questions consumed by the selected branch.

## What was tested

Initial screen: 3/4 fixtures matched their declared label/range. H01-4 returned 0.83 and 0.86 for invented interpretations of 'Do it'. The semantic component is not qualified to establish a task target. The controller requires an independently bound target and fails closed when it is absent.

Hold for grounding redesign; guarded prototype only Small author-labeled synthetic cases do not demonstrate field accuracy, calibration, cost savings, safety, or end-to-end harness integration. See [the evaluation]({{ '/iterations/01/evaluation/' | relative_url }}) and the raw synthetic receipts in the repository.
