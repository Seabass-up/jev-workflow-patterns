# E27: Classify generated repair semantic impact

Distinguish formatting or constrained canonicalization from a repair that changes meaning before any write is considered.

## State contract

Supply a compact named JSON object with these required fields:

- <code>original_artifact</code>
- <code>proposed_repair</code>
- <code>repair_policy</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>impact_class</code>.

~~~json
{
  "impact_class": {
"type": "choice",
"instructions": "How does proposed_repair change original_artifact under repair_policy? Classify semantic impact only. Do not apply the repair, calculate a diff, waive tests, or infer behavior outside the shown artifact.",
"criteria": {
  "format_only": "The change only alters whitespace, ordering where policy proves order-insensitivity, or other nonmeaningful presentation under the stated policy.",
  "permitted_canonicalization": "The change normalizes a specifically allowed representation while preserving the same named values and stated semantics.",
  "meaning_changing": "The change adds, removes, alters, or reinterprets a value, condition, policy, behavior, or source claim.",
  "unknown": "The supplied artifact/policy does not make semantic impact clear."
}
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** For anything other than format-only under an explicit policy, require deterministic diff checks, tests, and an authorized human/owner decision.

**Code and governance own:** Diff generation, formatting, policy enforcement, writes, tests, version control, and deployment.

**Simpler baseline:** Treat every generated repair as a manual semantic code review.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike E07's repair-versus-reproduced-failure relation, this is a change-impact classification that holds all nontrivial generated edits for deterministic diff and test review.

## Limits and source

It cannot establish behavior preservation, policy validity, or permission to modify an artifact.
