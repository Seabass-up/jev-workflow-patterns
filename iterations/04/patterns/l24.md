# L24: Classify semantic feature-question validity

Reject feature questions that leak the target, duplicate existing signals, or cannot be observed from permitted text.

## State contract

Supply a compact named JSON object with these required fields:

- <code>feature_question</code>
- <code>target_definition</code>
- <code>available_evidence</code>
- <code>existing_features</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>feature_quality</code>.

~~~json
{
  "feature_quality": {
"type": "choice",
"instructions": "How suitable is feature_question as a semantic feature for target_definition using available_evidence and existing_features? Do not train a model, inspect held-out labels beyond what is supplied, or claim predictive value.",
"criteria": {
  "observable_nonleaking": "The question can be answered from permitted evidence and does not directly encode the target/outcome or duplicate a named feature.",
  "redundant": "The question substantially duplicates an existing named feature without a stated distinct measurement purpose.",
  "target_leaking": "The question directly asks for, restates, or reliably exposes the target/outcome that a later model is meant to predict.",
  "underspecified": "The question, target, evidence, or existing feature set is too incomplete to judge."
}
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Hold non-observable, redundant, or leaking candidates; evaluate accepted questions only with versioned features and held-out outcomes.

**Code and governance own:** Dataset construction, label access, training, feature selection, metrics, deployment, and decisions based on predictions.

**Simpler baseline:** Let an LLM propose and train every textual feature without a preflight review.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L06's proposed memory-update category and H20's human-adjudication ledger, this is a pre-training feature-contract review that explicitly isolates leakage and redundancy.

## Limits and source

A non-leaking label does not prove usefulness, fairness, causal validity, or model performance.
