# CN07 — Schedule note states a critical-path impact

[Construction catalog]({{ '/construction/' | relative_url }}) · [Evaluation and limitations]({{ '/construction/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/construction.md)

Classify whether a schedule note states that a milestone or the completion date moves, that a delay is absorbed by float, that an activity is delayed with no stated impact, or that there is no delay.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/construction/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Flags the narratives and notices that claim a completion-date impact for the scheduler's attention without anyone computing dates, while the schedule itself remains the authority.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `schedule_note`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Complete synthetic example

This is fixture `CN07-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "schedule_note": "Week 31 schedule narrative, Brightwater Pharmacy, prepared by the Kestrel Builders scheduler. Exterior masonry started eleven working days late because the veneer brick arrived after the scaffold was already up. The masonry activity carries enough float that the substantial completion date is unchanged and the critical path still runs through the elevator, not the envelope. The contract milestone for building dry-in, however, now forecasts nine working days later than its baseline date, and the owner's early server-room move-in, which depends on dry-in, will move by the same amount. No time extension is requested at this time."
}
```

Expected label: `milestone_or_completion_moves`.

The note says float absorbs the masonry delay and that completion and the critical path are unchanged, which reads like absorbed_by_float, but it also states that a contract milestone moves, and the contract selects milestone_or_completion_moves whenever any milestone moves even if other float remains.

## Code-owned responsibilities

Code owns the schedule, the float and date calculations, the contract's notice deadlines, and any time-extension request; the label reads what the note states, and the scheduler's analysis is authoritative.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One re-check after the scheduler adds an impact statement when the label is delay_impact_unstated.

## Verification recipe

Compare labels with the scheduler's recorded impact for a project's schedule narratives and subcontractor delay notices; review every note labeled no_delay_stated or absorbed_by_float that later supported a time-extension request.

This describes required verification work, not checks already performed.

## Source inspiration

- [Wikipedia: Critical path method](https://en.wikipedia.org/wiki/Critical_path_method) (CN-S4). Explains that critical activities have no float and cannot be delayed without lengthening the project, that non-critical activities carry float, that the technique is widely used to plan and control construction projects, and that as-built critical path analysis is used to assess the causes of a delay. Motivates CN07 as a reading of whether a note states a milestone or completion impact versus float absorption, and CN02's separation of stated delay causes; all float and date computation stays in the scheduling software. Motivation only, not evidence of Jev performance.

These sources motivate the design problem and its boundaries. They do not demonstrate Jev performance on this question.
