# H30: RAG lane ledger with separate counterevidence

Preserve which passage signals caused evidence, conflict, and drop context lanes to be assembled separately.

## State contract

Supply a compact named JSON object with these required fields:

- <code>query</code>
- <code>passage_ledger</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>evidence_lane</code>, <code>counterevidence_lane</code>, <code>instruction_exclusion</code>.

~~~json
{
  "evidence_lane": {
    "type": "noul",
    "instructions": "Does passage_ledger contain a passage explicitly marked relevant and answer-bearing for query without an instruction-like content signal?",
    "criteria": {
      "true": "At least one supplied ledger entry meets all named evidence-lane conditions.",
      "false": "No supplied ledger entry meets all named evidence-lane conditions."
    }
  },
  "counterevidence_lane": {
    "type": "noul",
    "instructions": "Does passage_ledger contain a relevant passage explicitly marked as conflicting with a premise asserted by query and not instruction-like?",
    "criteria": {
      "true": "At least one supplied ledger entry meets all named counterevidence-lane conditions.",
      "false": "No supplied ledger entry meets all named counterevidence-lane conditions."
    }
  },
  "instruction_exclusion": {
    "type": "noul",
    "instructions": "Does passage_ledger contain an entry marked instruction-like that code must exclude from all answer context lanes?",
    "criteria": {
      "true": "At least one supplied ledger entry is explicitly marked instruction-like.",
      "false": "No supplied ledger entry is explicitly marked instruction-like."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Code copies only source IDs into separately labeled evidence and counterevidence blocks, excludes instruction-like entries, and preserves each routing reason.

**Code and governance own:** Ledger integrity, source text, routing thresholds, prompt assembly, answer generation, and all tool permissions.

**Simpler baseline:** Put all retrieved text into one undifferentiated context window.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L14's single-passage semantic signals, this controller consumes a recorded multi-passage ledger and constructs auditable, separate context lanes.

## Limits, source, and shared skill

It is not a standalone prompt-injection defense, source-truth verifier, or answer-quality guarantee.
