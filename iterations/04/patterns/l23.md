# L23: Classify primitive or composition fit

Choose an output type that matches the desired JSON consumer before writing a brittle prompt-and-parse contract.

## State contract

Supply a compact named JSON object with these required fields:

- <code>decision_description</code>
- <code>downstream_policy</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>representation</code>.

~~~json
{
  "representation": {
"type": "choice",
"instructions": "What TypeSafe representation best fits decision_description and downstream_policy? Choose based on what the code needs to consume. Do not create questions, invoke a model, or claim that a representation makes the decision correct.",
"criteria": {
  "choice": "One mutually exclusive bounded label should be selected from a defined answer space.",
  "score": "The code needs an ordered degree along a concrete rubric rather than a category.",
  "noul": "The code needs an independently useful probability that one stated condition is true.",
  "composite_or_no_fit": "The task needs several independent judgments, deterministic calculation, open generation, or another capability rather than one primitive."
}
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Have code/owners write the exact criteria, no-match handling, and controller; split composite cases into independently testable questions.

**Code and governance own:** Question schema creation, thresholds, action policy, deterministic calculation, and execution.

**Simpler baseline:** Use one free-form text prompt and parse its answer for every decision.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L18's decision-depth label and H24's downstream score/veto composition, this is an authoring decision about the JSON primitive shape before an application contract exists.

## Limits and source

The representation fit is advisory and does not replace domain evaluation or provide a complete workflow design.
