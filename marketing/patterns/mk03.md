# MK03 — Copy asks the reader for one action, several, or none

[Marketing catalog]({{ '/marketing/' | relative_url }}) · [Evaluation and limitations]({{ '/marketing/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/marketing.md)

Classify whether a piece of copy contains a single call to action, more than one, or none.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/marketing/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

<div class="callout warning"><p><strong>Provisional.</strong> At least one screening case disagreed with its authored label or did not complete. The disagreement is preserved on the evaluation page; neither the contract nor the label was changed after inference.</p></div>

## Proposed benefit

Flags copy that competes with itself or never asks for anything before it reaches a reviewer, without deciding what the call to action should be.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `copy_text`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 4 options, that floor is equivalent to a top probability of 0.85; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `MK03-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "copy_text": "Picture the last time you stood waiting for a kettle. Now ask yourself what you could have done with those four minutes. Keep reading and we will show you how the Quillstone kettle brings a litre to a rolling boil in ninety seconds, why its handle stays cool to the touch, and what our engineers gave up to make it happen. The full story continues below."
}
```

Expected label: `no_call_to_action`.

Every imperative here (picture, ask yourself, keep reading) invites the reader to imagine something or to continue within the copy itself. The contract counts only requests to do something outside the copy, so none of these is a call to action despite the imperative mood.

## Code-owned responsibilities

Code supplies the copy as written for one placement, records the placement's own rule about how many calls to action it allows, and routes multiple_calls_to_action and no_call_to_action to the copy reviewer. The label does not choose the call to action.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

None; the reviewer resolves competing asks.

## Verification recipe

Compare labels with the copy reviewer's notes on a month of drafts; review every draft the label called single that the reviewer marked as competing asks.

This describes required verification work, not checks already performed.
