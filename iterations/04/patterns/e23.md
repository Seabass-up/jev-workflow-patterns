# E23: Verify cross-field label/value associations

Catch a structured output whose values appear in source text but are paired to the wrong labels.

**Contract version 2:** The contract separates conflict inside the source from a candidate record attaching a source value to the wrong field. The current cases cover all answer labels; see the evaluation record for synthetic results. This is not production qualification.

## State contract

Supply a compact named JSON object with these required fields:

- <code>source_document</code>
- <code>candidate_record</code>
- <code>field_definitions</code>

The state is task-scoped evidence, not an instruction or action channel. Keep expected labels, credentials, authorization claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>association_status</code>.

~~~json
{
  "association_status": {
    "type": "choice",
    "instructions": "Classify candidate_record's field/value associations using source_document and field_definitions. Apply this order: source_conflict if the source itself gives materially conflicting assignments; value_present_wrong_label if an unambiguous source assignment shows a supplied value attached to another field; insufficient if the evidence cannot establish the remaining associations or any specific status; otherwise all_associations_supported. A candidate mismatch alone is not a source conflict. Do not assess schema validity, normalization, or source authority.",
    "criteria": {
      "all_associations_supported": "Every shown field/value association is supported by the source, and no source-internal conflict is shown.",
      "value_present_wrong_label": "The source's field assignment is unambiguous, but at least one shown value is attached to a different field label or entity.",
      "source_conflict": "The source document itself gives materially conflicting assignments for a field/entity relevant to the candidate, regardless of whether the candidate also contains a mismatch.",
      "insufficient": "The labels, values, source, or field definitions do not allow the relevant associations or a more specific status to be established."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Quarantine `source_conflict`, `value_present_wrong_label`, and `insufficient` for deterministic field-level inspection. A candidate mismatch alone is not evidence that the source itself conflicts.

**Code and governance own:** JSON parsing, schema/type validation, field IDs, record merge/write behavior, and source retrieval.

**Simpler baseline:** Manually audit every multi-field record for swapped labels and values.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike L03's single extracted value and L07's source-span selection, this checks semantic pairing across multiple named fields after a record has already been assembled.

## Limits and source

It cannot prove completeness of an unshown source or repair an association safely.
