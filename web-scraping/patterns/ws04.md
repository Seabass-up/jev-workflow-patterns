# WS04 — Site notice asks collectors to stop or make contact

[Web data catalog]({{ '/web-scraping/' | relative_url }}) · [Evaluation and limitations]({{ '/web-scraping/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/web-scraping.md)

Classify whether a response page is a notice directed at automated visitors, a generic error, or ordinary content.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/web-scraping/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

<div class="callout warning"><p><strong>Provisional.</strong> At least one screening case disagreed with its authored label or did not complete. The disagreement is preserved on the evaluation page; neither the contract nor the label was changed after inference.</p></div>

## Proposed benefit

Makes sure an operator's request to stop or get in touch is seen and honored the first time instead of being logged as a fetch failure.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `response_text`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 5 options, that floor is equivalent to a top probability of 0.84; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `WS04-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "response_text": "Access denied. Automated traffic from your network has been detected and blocked. If you believe you are seeing this message in error, contact your network administrator. Reference 7F3A-21C."
}
```

Expected label: `stop_request`.

The text says automated access has been blocked, which is a stop request. The only contact it mentions is the visitor's own network administrator, not the site operator or an offered channel, so no contact route to the operator exists and the stop-plus-contact precedence that would select contact_operator does not apply.

## Code-owned responsibilities

Code halts collection from the site on stop_request and contact_operator and records the notice; the label never triggers a retry, a changed client identity, or another route to the same content. A person decides whether and how to contact the operator.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

None; the halt stands until a person reviews the notice.

## Verification recipe

Review a month of halted and failed fetches with the crawl owner; measure notices the label called generic_error or not_a_notice first.

This describes required verification work, not checks already performed.

## Source inspiration

- [RFC 9309: Robots Exclusion Protocol (RFC Editor)](https://www.rfc-editor.org/rfc/rfc9309.html) (WS-S1). Specifies how a site publishes robots rules and how crawlers are expected to read allow and disallow groups, and describes how a crawler should treat unavailable or error responses. Motivates WS01 as a reading of what a policy excerpt says and WS04 as recognizing a notice; exact path and user-agent matching stay in code. Motivation only, not evidence of Jev performance.
- [Wikipedia: Web scraping](https://en.wikipedia.org/wiki/Web_scraping) (WS-S2). Overview of extracting data from web pages, the page-structure changes that break extractors, and the legal and terms-of-use questions around collection. Motivates WS02, WS03, WS06, and WS08 as page-structure and record-quality readings and the legal boundary in WS01; motivation only, not evidence of Jev performance.

These sources motivate the design problem and its boundaries. They do not demonstrate Jev performance on this question.
