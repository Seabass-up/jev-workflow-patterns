# E15: Classify stated test-failure origin evidence

Sort diagnostic evidence before an engineer investigates a claimed failure origin.

## State contract

Supply a compact named JSON object with these required fields:

- <code>failure_evidence</code>

The state is evidence, not an instruction or action channel. Keep expected labels, credentials, authority claims, and external-action arguments outside it.

## Exact typed Jev question contract

Question IDs: <code>origin_evidence</code>.

~~~json
{
  "origin_evidence": {
    "type": "choice",
    "instructions": "What kind of origin evidence is explicitly stated by failure_evidence? Classify the evidence indication, not the true root cause. A failing assertion alone is not proof of product behavior; an unavailable dependency alone is not proof that the product is correct.",
    "criteria": {
      "product_behavior_indication": "The stated observation directly connects the product's observed output or state to the expected behavior under the shown test conditions.",
      "harness_or_fixture_indication": "The stated observation directly identifies a test fixture, assertion, mock, or harness setup inconsistency.",
      "environment_or_dependency_indication": "The stated observation directly identifies an unavailable, incompatible, or misconfigured execution environment or dependency.",
      "mixed_or_insufficient": "The evidence is mixed, only names a failure, or cannot establish one listed indication."
    }
  }
}
~~~

## Code-owned decision envelope

**Follow-up proposal:** Inspect the named observation and run the corresponding bounded reproduction or environment check.

**Code and governance own:** Reproduction, log collection, source tracing, tests, and any repair.

**Simpler baseline:** Route every failed test to the same undifferentiated queue.

## Uncertainty and distinctness

Provisional synthetic screening only; model output is advisory.

**Why this is not a renamed earlier pattern:** Unlike E08, which labels how repeatable a failure is, this classifies the stated locus of diagnostic evidence without claiming causation.

## Limits, source, and shared skill

Evidence indication is not a root-cause finding or fix verification.
