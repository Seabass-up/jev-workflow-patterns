# AP05 — Described change calls for re-inspection under the supplied rules text

[Auto performance catalog]({{ '/auto-performance/' | relative_url }}) · [Evaluation and limitations]({{ '/auto-performance/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/auto-performance.md)

Classify what a supplied rules text says about re-inspection, re-certification, or notification for a described change to a vehicle.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/auto-performance/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Answers the recurring question of whether a change needs to go back through tech or be declared, from the rules text the organizer or authority supplied, without the model deciding eligibility.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `change_description`
- `rules_text`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

## Policy recorded with its option count

Review when confidence is below 0.8. With 5 options, that floor is equivalent to a top probability of 0.84; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `AP05-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "change_description": "Since the last tech inspection I have changed to a different brake pad compound in the factory calipers, bolted a rear wing to the trunk lid, and added a pair of auxiliary driving lights to the front bumper.",
  "rules_text": "Brake pad and rotor changes that keep the original calipers do not require a new technical inspection. Aerodynamic devices that extend beyond the bodywork by more than the allowed measurement listed in the appendix must be presented for re-inspection before the car runs; devices within that measurement do not need re-inspection. Lighting is not covered by this document."
}
```

Expected label: `threshold_dependent`.

No item is required to be re-inspected outright: the pads are explicitly exempt, the wing's requirement turns on a measurement, and lighting is not addressed. For a multi-item change the contract selects threshold_dependent before not_addressed and no_reinspection_stated, and it does not evaluate the measurement.

## Code-owned responsibilities

Code supplies the current rules excerpt and its revision, evaluates any numeric threshold the rules set, records the inspector's or authority's own determination as authoritative, and never lets a label admit a vehicle to an event or a register.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

One re-check after code evaluates the threshold when the label is threshold_dependent.

## Verification recipe

Compare labels with the tech inspector's or authority's determinations for past changes; review every no_reinspection_stated label that the inspector later overruled.

This describes required verification work, not checks already performed.

## Source inspiration

- [GOV.UK: Change vehicle details on a V5C registration certificate](https://www.gov.uk/change-vehicle-details-registration-certificate) (AP-S4). A registration authority's public list of vehicle changes that must be declared, such as engine, cylinder capacity, fuel type, and chassis or bodyshell, with like-for-like replacements reported separately and some changes the authority may inspect. Motivates AP05 as a reading of what a supplied rules text says about a described change; the authority's rules stay in code and with the authority. Motivation only, not evidence of Jev performance.

These sources motivate the design problem and its boundaries. They do not demonstrate Jev performance on this question.
