# FN08 — Bank memo wording is consistent with the described transaction purpose

[Finance catalog]({{ '/finance/' | relative_url }}) · [Evaluation and limitations]({{ '/finance/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/finance.md)

Check whether the free-text memo on a bank line agrees with what the ledger says the transaction was for.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/finance/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Surfaces reconciling items whose memo names a different counterparty or purpose, while amounts, dates, and exact references are matched in code.

This is a proposed benefit, not an observed outcome. All fixtures on this page are synthetic.

## Required named state

Supply the following named fields as the evidence packet:

- `bank_memo`
- `expected_purpose`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. The live missing-input case below probes the contract wording, not that gate.

```json
    }
  }
}
```

## Policy recorded with its option count

Review when confidence is below 0.8. With 4 options, that floor is equivalent to a top probability of 0.85; a threshold is not portable to a contract with a different option count. These values are provisional workflow policy, not calibration.

## Complete synthetic example

This is fixture `FN08-4`, from the **challenge** split. Its author received the question contract without the design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "bank_memo": "CORVANE SOFTWARE LTD - SECURITY DEPOSIT OFFICE SUBLET Q4",
  "expected_purpose": "Outgoing payment to Corvane Software Ltd (billing@corvane.example) for the annual platform licence renewal, our reference INV-EX-512; the ledger codes it to software subscriptions."
}
```

Expected label: `inconsistent`.

The memo names the same counterparty but states a purpose of a different kind (an office sublet security deposit rather than a licence renewal), and the contract's instructions make a purpose of a different kind inconsistent even when the name matches.

## Code-owned responsibilities

Code matches amounts, dates, and exact references, marks the reconciling item, and leaves the final match to the preparer and reviewer; the label only reads the memo wording.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

None; uninformative or unknown memos go to the preparer with the code-matched candidates.

## Verification recipe

Compare labels with the matches the reconciliation preparer confirmed on prior months; review every inconsistent label the preparer matched anyway.

This describes required verification work, not checks already performed.
