# HA11 — Does an error message tell the person how to recover?

[Human + AI catalog]({{ '/human-ai/' | relative_url }}) · [Evaluation and limitations]({{ '/human-ai/evaluation/' | relative_url }}) · [Kernel reference module](https://raw.githubusercontent.com/Seabass-up/jev-workflow-patterns/main/skills/jev-question-kernel-catalog/references/human-ai.md)

Check whether a displayed input-error message gives a correction that fits the known field rule.

This is a proposed, bounded text judgment. Consult the [evaluation record]({{ '/human-ai/evaluation/' | relative_url }}) for observed results; the fixture labels below are intended outputs.

## Proposed benefit

Can distinguish actionable recovery instructions from merely announcing that an error occurred.

This is a proposed benefit, not an observed human outcome. All fixtures on this page are synthetic. No study with people was conducted for this catalog, and the question must not be used to infer a person's traits, ability, diagnosis, or intent.

## Required named state

Supply the following named fields as the evidence packet:

- `rejected_input`
- `field_rule`
- `error_message`

Code deterministically returns `unknown` without invoking Jev when any required named field is absent or empty; the model is not the required-field gate. Preserve the exact source revision. Any remaining insufficiency or ambiguity follows the question's `unknown` criteria; a model label cannot establish missing facts.

    }

## Complete synthetic example

This is fixture `HA11-4`, from the **challenge** split. Its author received the question contract without the original design fixtures or model results; the expected label is an authored interpretation of the contract, not a Jev prediction.

```json
{
  "rejected_input": "ABC-DEF",
  "field_rule": "The public sample code must contain exactly six uppercase letters, with no spaces or punctuation.",
  "error_message": "This sample code cannot contain a hyphen. Do not add another character; remove the hyphen and enter ABCDEF."
}
```

Expected label: `usable_correction`.

The message identifies the rejected punctuation and supplies a concrete corrected value that satisfies the six-letter rule. Its negative wording does not prevent recovery guidance.

## Code-owned responsibilities

Validate the actual field format with code, decide what recovery details are safe to disclose, bind the exact displayed message, and verify keyboard/screen-reader announcement independently.

The judgment is advisory. Code and the responsible person retain control of exact identifiers, data access, state changes, and consequential verification.

## Bounded follow-up

If the correction is misleading or absent, inspect the exact validator rule once and draft a compatible suggestion for a person to approve.

## Verification recipe

Submit invalid and valid inputs against a local/test form; inspect actual messages and recovery behavior. Test that the suggested example passes validation and does not conceal another error. This is not a complete accessibility audit.

This describes required verification work, not checks already performed. Separate agreement with synthetic expected labels from successful execution of the real workflow and from any measured benefit to a person.

## Source inspiration

- [W3C WAI: Understanding SC 3.3.3 Error Suggestion](https://www.w3.org/WAI/WCAG22/Understanding/error-suggestion.html) (HC-S3). The explanation distinguishes notifying a user of an input error from providing an appropriate known correction. Suggestions may be withheld if they would jeopardize security or the content's purpose. The proposed pattern checks semantic correction guidance only, not complete WCAG conformance.
- [W3C WAI: Use Clear Step-by-step Instructions](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o4p07-step-instructions/) (HC-S8). This guidance recommends complete, clearly located instructions and examples before a user needs to act, rather than introducing requirements only after an error. The patterns target content relationships; no reader ability or disability is inferred.

These sources motivate the design problem and its boundaries. They do not demonstrate Jev performance on this question. Source summaries and recorded provenance are available in [sources JSON]({{ '/human-ai/sources.json' | relative_url }}); supplemental accessibility guidance is not a full conformance assessment.
